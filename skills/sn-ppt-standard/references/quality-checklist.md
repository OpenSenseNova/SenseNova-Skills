# 质量检查清单(单页 + 整套)

幻灯片质量的统一判据分三部分：

- **单页检查** —— 一页能否清楚表达、稳定专业。**slide subagent 自检** 与 **review subagent 逐页复核** 都用这套。
- **整套检查** —— 整份能否围绕目标顺畅讲完、多页风格统一。**review subagent 横扫全套** 用这套。

通用优先级:**先硬后软**——能直接毁掉一页的「硬伤」(见单页·维度4)必须先清零,再谈层级 / 美感这类「软伤」。

阅读路由：Slide Group 只读「一、单页检查」和相关 lint；Review 先读「二、整套检查」，再用单页与 lint 定位问题。不要把本文件当生产前置全文。

## 目录

- 一、单页检查:表达与内容逻辑、视觉语义与解释力、版式组织与阅读路径、可读性与技术完成度、视觉元素与风格适配
- 二、整套检查:目标场景、全篇结构、视觉系统一致性、构图密度、基础美学、美术指导、展示风险
- 三、可机核 lint 项:可由脚本直接扫出的 anti-slop / 技术硬伤
- 怎么用:slide subagent 与 review subagent 的分工

---

## 一、单页检查

一页要同时立得住:**内容讲得清 + 视觉撑得住**。

### 1. 表达与内容逻辑
- 主题 / 重点 / 结论清楚;**标题与正文指向同一表达目标**(不跑题、不各说各的)。
- 论证信息**支撑页面主旨**(数据 / 论据服务于这页要说的那一件事)。
- **完成当前页型任务 + 必含要素**(案例页有具体案例、介绍类有代表作品、数据页有真实 / 标注数据、方案页有具体做法……见 SKILL.md 页型词表后的清单)。〔页型名按 deck 语言可能是中文或英文 role(结束页=Closing、案例页=Case Study 等),按**页型语义**认,别因字面语言不同而漏判。〕
- **文本与规划一致**:上屏文字只能来自逐页计划的 `## 最终屏显文案`，且未被改写 / 扩写 / 编造。`主体/受众/目标/页面角色/制作组/视觉验收/素材路线/来源/文件路径/证据编号/内部状态` 等规划字段只供生产使用，不得原样上屏；页面主题本身确需讨论受众或目标时，应写成面向听众的正常正文，不显示字段标签。无自创页眉、水印、「机密·内部使用」、伪日期、伪档案号或多余装饰文字。普通内容页由 base.css 提供且计划允许的 `.slide-footer` + `.page-no` 不算自创；封面与结尾页默认不显示这些家具。
- **辅助文字有观众价值且不重复**:主题、作品名、章节号、年份和场合各出现一次即可；`SCENE 00 / COVER`、`END / NN`、`A VISUAL ESSAY`、虚构坐标/档案号、重复页数/时长等伪元数据没有实际信息价值时不得上屏。删掉后信息与构图都不受损的标签，应删除而不是换个角落继续放。
- **内容充分且屏显语义唯一**:普通内容页应有不可替代的听众所得，并由证据、机制、对比、案例、行动或边界中的合适一层继续解释；只有主题句、同义副题和状态角标不算内容成立。横向比较标题、kicker / subtitle、图片角标、badge、callout、图例与页脚，同一短语通常只保留一个最强载体；导航或同屏比较确需重复时，每次出现必须承担不同作用。
- **标点全 / 半角跟着语言走(全 deck 一致)**:中文段落用全角(`，。：；！？「」`)、英文用半角,**一句里不中英混标点**;数字 / 代码 / 日期 / 百分比 / 缩写等半角语境例外。**扫到中文字后紧跟半角 `,` `.` `:` `;` = 不合格**(如 `间,` `来源:` `径;`)。
- 内容本身无逻辑问题(因果 / 顺序 / 归类不自相矛盾)。**事实准确性**:每条上屏事实能追溯到当前 `outline.md`、Entry/Story 已交接的 Research 产物或对应页 `speech.md` 的参考资料，或已标「示意 / 待核」；涉及具体人 / 作品无明显错误(性别 / 称谓 / 归属)。〔注:准确性的上游关口是 Entry Research / Material → `info_pack.json` → Story `outline.md`；Standard、Slide 和 Review 不重新研究、不重新解析材料，也不把页面实现推断写成新事实。〕
- **生产来源不上普通页**:`research` / `materials` / `grounded-knowledge` / `plan` 路径、证据编号和内部 URL 不出现在普通页面文字中。真实外部出处默认写入逐页规划的 `## 来源`,由脚本汇总到 `speech.md` 的「不朗读」区；用户或交付场景明确需要屏显参考文献时，可使用独立 references 页，以面向听众的标准引文呈现，不泄漏内部路径或生产标签。示意数据仍在页面本身标「示意 / 自拟」。

### 2. 视觉语义与解释力
- **先对照逐页计划的“视觉验收”**：不看 HTML 注释和讲稿，只看最终像素，观众是否能复述计划要求的对象、关系、方向和结论。技术上完整但无法回答该问题，仍不合格。
- **语义一致**：标题、副标题、图例、节点标签、箭头方向和结论使用同一组对象与关系。不能标题说 A→B、图例写 B—样本、图中又没有方向；代码注释不能被用来替像素解释矛盾。
- **关系编码可读**：表达流程、因果、传递、反馈或时间的连线必须有清楚端点和方向；需要方向时使用箭头或等价的明确编码。无箭头虚线、弧线和散落线段若不能被解释，只是装饰，不算信息图。
- **领域特征足够具体**：科学/技术/医疗/工业/方法页要呈现该领域可辨认的对象或输出，如真实/忠实简化的光谱、显微图、CT 截面、样本、仪器状态或检测结果。圆、矩形、六边形等通用几何只有在映射明确并确实适合抽象层级时才成立，不能替代领域证据。
- **解释达到页面职责**：页面若要比较六种方法，视觉至少应帮助观众区分它们测什么、适用什么或产生什么证据；只列名称，再配一个“物体—仪器—数据”的泛化占位，不算解释完成。
- **视觉占用与信息权重相称**：主图、图表或机制图使用计划分配的主要区域，不缩成中间窄条；大面板中的空白必须承担分组、方向、对比或呼吸，而不是未完成区域。边框面积不等于内容占用：卡片/侧栏即使铺满页面，有效内容若只贴在上下沿、中部长期闲置，仍是不完整构图。优先启用相关图片、界面、图表或解释视觉，或缩小/重组容器；不靠随机图标和装饰填空。
- **开放式复述测试**：Vision 先回答“你从这张图读出了什么、方向是什么、哪些元素是领域证据”，再与计划对照；不要只问“是否美观/是否溢出”的是非题。

### 3. 版式组织与阅读路径
- 有**明确视觉中心**,主次层级清楚(一眼知道先看哪)。
- 排版稳定美观(对齐、网格、留白均衡,不挤不空)。
- **观看顺序顺畅**(视线自然流动,不跳来跳去)。
- 装饰**不干扰阅读**(纹理 / 形状 / 图标是辅助,不抢内容)。

### 4. 可读性与技术完成度
- 关键信息清楚可读(字号够大、对比够、不被压盖)。
- **最小字号 ≥ `--fs-min`**(投影场景可读);没有为塞内容把字缩到看不清。
- 表达元素**完整呈现**,能读出主要含义(图表有轴 / 图例 / 标签,不是半截)。
- HTML 导出质量清晰稳定(不糊、不截半截)，全部最终 PNG 与 `present.html` 已基于同一版页面重新生成并验证；
- 当 `choices.static_postprocess` 包含 `pptx` 时，派生 PPTX 存在、可以打开且页数与最终 HTML 一致；PPTX 失败不否定已验证的 HTML 产物，但任务状态必须为 `partial`、必须保留原始错误，且不得登记不存在的 PPTX 路径。
- 画面无缺陷。

> **本维度的硬伤必须先清零，但检测器只提供候选，不提供审美裁决。**先看不带告警措辞的新鲜 PNG，再用 DOM / bbox 定位。`OVERFLOW`、`CROWDED`、`FOOTER-PUSHED`、`BROKEN-IMAGE` 等若证明内容真实被裁、推离画布或缺失，就是硬伤；`BOXOVERFLOW`、`OVERLAP`、`DECOR-OVERLAP`、`FOOTER-COVER`、`INNER-GAP`、`WIDOW-LINE`、`IMG-LONELY`、`COVER-OOB`、`SVG-SMALL` 等是诊断线索，只有最终像素或 DOM 证明确有遮挡、不可读、空洞或语义损失时才修。bbox 含透明行框，不能单独证明字形遮挡；不得为了“消 warning”删除好看的引号、增加白色托板、压缩主视觉或制造孤立标点。满铺背景 `.slide--bleed` 到边合规。
> ② 遮挡(文字 / 图表 / 图片 / 形状互相压盖),尤其页脚/页码被底图或装饰压住;
> ③ 占位残留(空框、占位文字、缺轴 / 图例 / 标签的半截图表);
> ④ 破图破表(`<img>` 或 ECharts 没真正渲染出来);
> ⑤ 中文豆腐块(□□□,字体没加载);
> ⑥ 可读性不足(文字对比太低看不清);
> ⑦ 概念图硬伤:大型示意图被缩成孤立小块 / 窄条,标签互撞 / 贴线 / 被连线压住。新页面默认使用 Canvas/图片 + HTML 标签；大型手写 SVG 属于媒介选择错误。旧页面的 `SVG-SMALL` / `SVG-LABEL-OVERLAP` 先由最终像素确认是否真的不可读，再修媒介或几何根因；
> ⑧ 配色出界(调色板外的红 / 粉 / 绿、ECharts 默认色、多系列没用 `--series-*` token、涨跌只靠色相而无 ↑↓/正负号、或涨色 = 警示色)——一律换回 base.css 的 token + 双通道。

### 5. 视觉元素与风格适配
- 各元素**协调**(配色 / 字体 / 图形语言一致)。
- 元素间有清楚层次,**视觉服务内容重点**(强调的是关键信息,不是装饰)。
- 视觉风格**贴合 deck 选定的 风格 / 色调 / 主色**(见 base.css 与 plan/deck.md)。
- **素材用得准**:无多余素材(每张图都承载内容);未被严重裁切毁主体、未拉伸变形、比例匹配槽位(对不上用 `contain` 或调整槽位，而非大裁)。按逐页 `crop_contract` 核对焦点与 `protected_parts`：人脸/头顶/手势、完整产品轮廓/Logo、作品主体、坐标轴/图例等承担识别或证据的部分不得缺失；背景边缘只有在合同允许时才可有意裁掉。主体透明元素必须有真实 Alpha，不得残留棋盘格、整块白底、明显白边/锯齿或被误删的头发、四肢和产品边缘。
- **图上托底无接缝**：scrim/蒙层不得在图片上留下明显的矩形边、黑带或不合理横线。角落托底应径向渐退或仅托住文字，不把有限黑色块伪装成“层次”。
- **特殊页修改不退化**：托板、色带或章节元信息若从首稿起承担明确的分区、节奏或叙事作用，可以成立；若只是为局部对比度临时增加，必须比较修改前后。局部文字更清楚，却导致主图被切断、视觉家具变重、重心和阅读路径变差，属于退化，应回滚或改成更局部的处理。
- 无**低质**效果(**无主题的**廉价渐变 / 滥用阴影毛玻璃 / 千篇一律的 AI 味套版;有主题色彩故事的渐变不算)。
- **层级自信**:标题明显大过正文(标题 ≥ ~2.1× 正文、小标题 ≥ ~1.45× 正文),密页上标题 / 正文 / 标签**不挤成一个字号档**;一眼能分出先看哪。
- **强调有主次**:accent 点在**真正要喊的几处**(不是标题线 / 眉签 / 要点 / 数字全染);单 accent 或主 + 次双 accent 由设计决策;正文 / 分隔线 / 标签用中性墨色浓淡。
- **别用 AI 默认色**:主色来自主题,不是顺手套"深藏青 + 霓虹青/电光蓝"默认科技色或 `#6366f1` 靛蓝(主题真要则有意声明);暗底有色温,accent 不刺眼(降饱和)。
- **面板有体积**:卡片 / 面板靠色调分层(页底→面板→内元素三级),不是扁平深色盒子;没有标题后那团泛用径向"光晕"假景深。
- **对齐**:同一页文字块**对齐到同一条网格线**,没有"居中块 + 左对齐块"两套对齐混用;长标题 / 长句的折行不是忽长忽短的烂 rag。**元素块之间也要对齐**(相邻卡片 / 面板 / 分区的边、内部行槽对齐到同一栅格),别块与块之间各飘各的。
- **同权重同款式**:同一层级 / 重要性的信息(并列小标题、并列数据项、同类标签 / 序号)用同一颜色 / 字体 / 字号 / 标号写法;变款式只为表达强调差异、且**变色 / 变号跟内容含义挂钩**,不是无逻辑地这块蓝那块橙。
- **色块 & 装饰收敛**:改色有逻辑、同类块共用颜色角色；无逻辑的多色块平均争抢注意力才是问题，不按块数判废。**克制 / 严谨型 deck**额外检查字体角色是否稳定、装饰是否承担信息或构图职责；严谨靠秩序、留白与层级，不靠无意义印章、徽标或母题。
- **标题跨页同锚点**:这页 `.slide-title` 的位置 / 字号 / 字体与其它内容页一致(没被改大 / 挪位 / 折行顶高);英文双语副题「要么都有要么都没有」。
- **数字 + 单位**:大数字的单位(亿 / % / 美元 / ×)是**小一号、退一步**(≈0.5× 数字、不抢戏),不是和数字一样大顶在一起;同一指标族单位 / 精度 / 千分位写法一致。
- **一排卡片对齐**:同一行的卡片**等高、内部各行(数字/标题/正文/脚注)落在同一条基线**,不是有的卡片矮一截、脚注高低参差。
- **卡内留白不过多**(见 design-rules §9⑩⑰):卡片 / 框内容量与框高匹配,没有"一卡挤满、一卡半空"。稀疏卡优先减高；同组必须等高且只有图标、标题和一行说明时，整个内容组在卡内垂直居中、文字保持左对齐。只含单个数字或极短状态才适合水平居中。卡内「正文↔脚注」分隔线只在真有分区时画,别让线悬在空中；**别用 `margin-top:auto` 在等高卡里裂出中缝**(`⚠ INNER-GAP`),别用 `repeat(N,1fr)` 硬撑不等量文本导致溢出(`⚠ TEXT-OVERFLOW-BOX`)。
- **换行符合语义且无寡行**(见 design-rules §9⑪):所有主动 / 自动换行均落在标点、并列分隔或完整短语 / 语义单元之后，没有拆开动宾短语、偏正短语、固定搭配或语义尚未闭合的片段；一行排得下的短语没被手动 `<br>` 断开；任何普通文本行，尤其末行，没有只剩 1–2 个汉字；容器没窄到把一句话逼成多行 + 孤字。
- **大标题不挤**(见 design-rules §9⑫):粗宋 / 得意黑等粗重字做大标题时,标题一行舒适排下、字有呼吸;标题过长时已降字号,而非硬撑满屏粗字;粗中文大字没叠负字距。
- **序号 / 大字与右侧标题顶端对齐**(见 design-rules §9⑯):大号序号(01/02…)与右侧小号标题**顶端齐平**,不是序号顶比标题顶低(错位根因 = 用了 `align-items:baseline` 或序号 `line-height:1`);页面内联重写 arch-index 时也守这条,别照抄 baseline。
- **封面 / 文字块重心不偏上**(见 design-rules §9⑭):封面 / hero / 过渡页文字块视觉居中或有意构图位,没把标题贴顶、下方留一大片无理由空白。
- **过渡页简洁而不空壳**：章节号、标题与一句承诺形成清楚的主信息团；图片、主题母题、色场、裁切或超大排印至少有一种成为视觉对重。留白能解释为聚焦、方向、纵深或换场，而不是文字没铺到的剩余画布。不得用补正文卡片来假装充实。

## 二、整套检查

全套要能**围绕目标顺畅讲完**,且**多页之间风格统一**。

### 1. 目标场景
- 适配**汇报场景 / 展示对象**(受众、媒介、正式度都对得上)。
- 有 `plan/design-brief.md`,且设计契约说清**受众 / 场合 / 材料质地 / 视觉媒介 / 参考取用 / 禁区**;成品看得出这些判断被执行。

### 2. 全篇结构与跨页推进
- 整体结构**清晰、完整、有效**(封面 → 铺垫 → 论证 → 总结 / 行动 → **结束页 / Closing(封底,必有)**,叙事弧线完整)。
- 相邻页**自然承接**(不断层、不重复、不突兀跳跃)。
- **长 deck 有清楚的幕结构**:章节数量与过渡页由叙事复杂度决定，不为满足固定数量机械拆章；真正发生主题、证据或节奏转向时再使用过渡页。`dividers` 共享字体角色、章节标记语法、标题锚点、色彩/图像处理与母题，但每章有不同 `chapter_state`、构图重心、裁切和视觉动作；`bookends` 的结尾明确回应封面。既不能像不同 Deck，也不能只复制同一模板换章节名。
- **是"搭建"不是"清单"**:有一个统领论点、每页回扣它(不是每页换个指标重说"很大");没有两页讲同一宏观点没合并。
- **密度有节奏**:没有无理由的满密页或极简页机械连排；一页围绕一个主判断组织，支撑信息数量服从内容和场景，不用固定条数把复杂论证削薄。
- **章节脚本不机械复制**:不同章节可以共享设计 DNA，但不能只是照抄同一套“痛点—案例前—案例后—步骤—工具”并替换对象名；相似案例拆开后若没有独立增量，应合并为有效对比，或分别承担诊断、证据与行动等不同任务。

### 3. 视觉系统一致性
- 页面元素**多页之间保持统一**(配色 / 字体 / 页眉页脚 / 页码 / 间距同一套 token)。
- **画布家族连续**：普通内容页共享同一基础明暗、色温和材质家族；章节差异优先落在局部色场、图片调色、条带或母题。整页换场必须能在“上一章末页 → divider → 新章首两页 → 章节退出页”中看出进入与退出承接，不能突然形成数页另一套 Deck 后又切回。
- **固定框架全套一致**:标题位置 / 页脚 / 页码 / 安全边距套同一 base.css 骨架,没有逐页漂移(标题忽大忽小、装饰线乱动、重心忽上忽下)。
- **素材视觉配方统一**(同媒介 + 同调色 / 处理,不风格色调乱飞):图标 / 图片 / 图表 / 形状用**同一种视觉语言**,别扁平 + 3D + 手绘 + 照片质感**混杂**——一个 deck 一种素材调性。底图 / 背景图不用低劣素材(噪点 / 低分辨率 / 拉伸变形 / 带外来水印)。
- **配图机会已兑现**:`image_opportunity_map` 选择真实图或生成图的页面有本地素材实际上屏，且图片承担证据、识别、场景或情绪职责；不能在计划中写了图片、成稿却静默退成纯文字/小图标，也不能把主视觉缩成角落里的象征性缩略图。页面以具名真实人物、主创或团队为核心时，检查是否使用了可核验的真实肖像/活动照/团队图，或记录了检索失败后的明确降级理由；“避免生成假真人”本身不是无图理由。
- **同类页型有稳定表达**(所有数据页一个调性、所有对比页一个结构)。
- 页间**视觉复杂度 / 信息密度 / 设计精度相对均衡**(不忽繁忽简、忽精忽糙)。
- 无个别页明显低质拖后腿。

### 4. 版面填充率 / 构图密度(★原质量门缺的轴,补上)
- **空间完成度判据**:一页技术全干净但主体缩成局部小团、剩余空间没有聚焦、对重、方向或呼吸职责，仍是不完整构图。每张普通内容页应能辨认一个主要视觉载体：真实/生成图片、图表、解释性 Canvas，或通过尺度、层级和构图真正成立的排印主视觉；空框、微型图标、装饰线与纯面板不能冒充。`SPARSE` 只提示检查空间归属，不能因某个固定填充率自动补元素；有明确 Hero、breathing 或非对称意图的留白应保留。更多视觉元素仍须组成主次清楚的一张画面，而不是平均散布。
- **低条目页(目录 / 3-条页)要撑满**:别靠 `justify-content:center` 把少量内容居中、上下留大条空;放大标题 / 序号字阶、条目做成撑满纵向的编号块、加锚定视觉。真只有 2–3 条 → 合并轻页或每条升维(加释义 / 数据 / 图元)。
- **禁行内 leader gap**:`auto 1fr auto`(标题左 + 英文右)让 1fr 段空着、中段大片空 = 不合格——加引导线 / 点划把左右连成一体、或拉近、或让内容占满该列。
- **纯装饰英文别喧宾夺主**:CONCEPT / ACTION 类装饰英文占显眼位、把真信息(「是什么 / 怎么办」)挤到边缘 = 主次颠倒、不合格;真信息更近更重,装饰英文弱化或去掉。

### 5. 整套美学气质(「好不好看 / 协不协调」的整体轴)
- **背景不丑不跑调**:满幅氛围图 busy / 低对比 / 浑浊 / 跑调 = 不合格——宁可干净纯底;**全册一套背景配方**,别每页各生各图导致**各布局类型乱晃**。
- **对比 / 配色纪律(管到装饰元素)**:圆环 / 线 / 英文 / 母题也要够对比——maroon 叠近黑看不清、低对比 gold = 不合格；色块与 accent 的数量由信息层级决定，但每一种颜色必须有角色且不平均争抢注意力；**禁无主题 glow / 径向渐变假景深**。
- **庄重题材不长成 keynote**:党政 / 政务 / 学术用近黑暗底 + 斜切大字 + 戏剧氛围图 = 调性错(见 `design-rules.md` §1 党政条 / §2 字体条),该换**直立衬线(思源宋体)+ 克制红金 + 干净底**。

### 6. 美术指导与反模板检查
- 全套形成**一致的视觉气质**(像一个人做的一整套,不是拼盘)。
- 视觉语言**匹配主题与媒介**。
- **有设计概念,不是模板填空**:这套 deck 看得出一个**贴主题的设计概念 / 色彩故事**(写在 `plan/design-brief.md` 与 `plan/deck.md`),不是"换个色的通用 AI deck"。
- **招牌视觉已兑现**:`visual_thesis / signature_visual` 不只停留在 Style Lock 文本里；规划指定的落点页必须真实出现对应的构图、媒介或母题动作，并成为可辨认的记忆点。若最终只能从 brief 读出、从 PNG 看不出，列为 must_fix；允许按实际成品诚实收窄定义，不允许用普通背景或小装饰冒充。
- **参考已被转译**:字体、版式、色彩、母题像是从本 case 的材料 / 受众 / 场合长出来,而不是把 `design-styles.md` 的成套配方或 `layout-patterns.md` 的原型原样照搬。若一眼像通用 recipe 换皮,列为 should_fix。
- **版式不单调**:**不是每页都"眉签→大标题→一排卡片"**。等权卡片/宫格只在信息确实平行且利于扫描时使用；一旦相邻页或整章形成机械重复，就改用图文、流程、对比、主视觉或数据构图，不按固定页数配额判断。
- **有视觉高点**:在真正的叙事高点用特大数字/词、满幅金句、主图、图表或其他适合主题的动作拉开节奏；克制型短 deck 可以用机制图或结论对比形成高点，不为满足数量硬造 hero。
- **母题贯穿**:封面母题在足以建立亲缘性的关键页面以变体回应；不只用一次就丢，也不为了凑复现次数机械贴装饰。
- **图表是新闻图**:数据页标题写**结论**(发现句)不写题目;图直接标值、砍冗余轴/图例;KPI 一排里只有一个当头条。

### 7. 整体展示风险
- 没有**大量页面反复出现同类问题**(同一毛病系统性复发 → 多半是 base.css / 规划层的根因,应改设计系统而非逐页修)。
- 无**缺页 / 重复页 / 顺序错误 / 章节标题与内容不匹配**。
- **最后一页必须是「结束页 / Closing」(封底式收束),且与前一页(总结 / 行动)版式明显不同**(不是又一张内容页);不含任何"感谢聆听 / 感谢阅读 / 感谢观看 / Thank you for listening / watching / reading"之类收尾套话(中英都禁,硬约束)。

## 三、可机核 lint 项(machine-checkable)

这些判据**能直接数出来 / 正则核 / 从 token 算**,不靠审美——slide 自检和 review 复核都能机械过一遍。逐条勾:

- [ ] **强调有主次(非到处染)**:accent(主 + 可选次)用在真正要喊的几处、有清晰主次,不是标题线 / 眉签 / 每个 KPI / 每根柱全染(那是「到处强调 = 没重点」);单色还是双 accent 由设计决策、不设死次数(见 `design-rules.md` §1)。
- [ ] **颜色 token(raw-hex)**:`:root`(base.css token 块)之外若反复出现裸 `#rrggbb`，检查是否发生页面级配色漂移；属于全册角色色的收回 `var()`，真正局部且有语义的派生色可以保留，不按固定数量判废。
- [ ] **P0 anti-slop 零命中**(精确清单见 `design-rules.md` §11「精确 anti-slop 清单」):没把 7 个靛蓝/紫 hex(`#6366f1`/`#4f46e5`/`#4338ca`/`#3730a3`/`#8b5cf6`/`#7c3aed`/`#a855f7`)当**顺手默认** accent(主题有意声明的不算);没有**无主题的**通用信任渐变(紫→蓝 / 蓝→青 / 靛→粉;有主题色彩故事的渐变不算命中);无 emoji 图标(✨🚀🎯⚡🔥💡📈🎨…);无编造指标("10× faster"/"99.9% uptime"/"3× more");无 filler(`lorem ipsum`/`feature one·two·three`/`placeholder text`);无圆角卡+左侧彩条 accent;无外部占位图 CDN(unsplash / placehold.co / picsum…)。
- [ ] **uppercase 字距(all-caps-no-tracking)**:每条 `text-transform:uppercase`(含 inline `style=`)必带 `letter-spacing≥0.06em`(建议 0.08em)。无字距的全大写是头号业余 tell。〔中文别用 `uppercase`。〕
- [ ] **display 负字距**:`≥48px` 的大标题带 `letter-spacing:-0.02em~-0.03em`(松垮的大字同样露怯;拉丁文,中文大标题不做过度负收紧)。
- [ ] **中文字体语义(cjk-typography)**:同一句标题、结论、按钮或标签优先使用一个字体家族，强调词优先只改颜色/字重/字号/装饰线；卡通、手写、书法体只在合题场景且显式标记时使用；所有中文字体栈保留 Noto Sans/Serif SC 兜底。`render.py` 的 `cjkTypography` 是 advisory 线索，不要求机械清零；只有新鲜像素或 DOM 证明缺字、不可读、真实裁切/遮挡或语义角色明显错误时才阻止交付。
- [ ] **对比度 gate(contrast-gate)**:正文对底 **≥4.5:1**、大字(>18px 或 14px 粗)**≥3:1**(可从 `base.css` 解析出的 token 色值算 WCAG 比,或在渲染图上取色比对)。不达标就把 text 用途换深一档(600 级)。
- [ ] **每张 slide 有明确明度角色 + 明暗节奏(slide-theme / slide-rhythm)**:每页归位到「常规内容底 / 加深过渡底 / 满铺 hero」等已声明状态之一，体例全套统一。节奏变化服务章节和叙事高点，不为了打破连续次数随机换底；发现长段页面视觉状态没有变化且阅读疲劳时，再用同色系明度、图片或色场状态建立转折。
- [ ] **骨架契约(layout-contract)**:root 直下只用标准 `.slide-title` / `.slide-body` / `.slide-footer`,正文内容尽量回到 `.slide-body` 的网格/flow。`render.py ⚠ CUSTOM-BODY` / `⚠ ABS-LAYOUT` 是**诊断告警(advisory)**、不是硬门:只有当新鲜像素确认它**真的**造成裁切、遮盖、下方溢出或不可读时才作为硬伤返修;若像素上构图完好(装饰/scrim 的绝对定位、或不影响阅读的自定义正文结构),记为 checker mismatch 保留,不为清零告警而破坏结构。真正的硬门只有 `broken` / `overflow` 与真实遮盖。
- [ ] **遮盖护栏(layout-guard)**:`DECOR-OVERLAP` / `FOOTER-COVER` 候选已逐项对照新鲜像素；真实遮盖为零。没有可见遮盖的 bbox 误报记录为 checker mismatch，不为了清零报告破坏构图。
- [ ] **概念图媒介(diagram-medium)**:大型流程 / 架构 / 机制图使用 Canvas 几何 + HTML 标签，或无文字图片 + HTML 标注；SVG 仅用于 icon/logo/箭头/小装饰。旧页面若保留大型 SVG，以最终像素确认标签、方向和主体真实可读，不按告警数量验收。
- [ ] **文本框溢出 / 卡内空洞(box-fit,见 §9⑩⑰)**:`render.py ⚠ TEXT-OVERFLOW-BOX`(文字撑出 panel/卡片/正文区)/ `⚠ INNER-GAP`(卡中间空一大块)必须为零;等分网格(`repeat(N,1fr)`)承载不等量文本改 `auto`+顶排、去掉不必要的 `margin-top:auto`、多区堆叠页不写死 `height:XXXpx`、封面巨字号用 `clamp()`/按字数降档不顶出安全区。
- [ ] **底部溢出(footer-fit,见 §9⑦⑪,最严重)**:`render.py ⚠ FOOTER-PUSHED` 必须为零——正文体量绝不能把页脚顶下去 / 压过页脚顶 / 挤出视口;放不下就减字 / 拆两页 / 换紧凑版式、定高区改 `minmax(0,1fr)`、守 `--body-safe-bottom`。
- [ ] **寡字 / 寡图(orphan,见 §9⑦⑱ / §6)**:`render.py ⚠ WIDOW-LINE`(末行 1-2 孤字)/ `⚠ IMG-LONELY`(位图孤立小图)尽量为零;文字块加宽 / 去多余 max-width 消孤字,位图放大 / 落网格 / 配说明 / 成组消孤图。
- [ ] **封面出界 + 完成度(cover,见 §9⑦⑰ / §6)**:`⚠ COVER-OOB` 为零(标题守 `--margin-x/y` 安全边、别堆左上角);主视觉与标题形成一个清晰焦点，必要的副题/真实身份信息/语义母题少而准确。封面不靠固定数量的“设计层”、伪元数据、重复标签、页脚或页码证明完成度。
- [ ] **配图形状不单调(shape,见 §6)**:配图不应无意识地全是同尺寸直角方块；按气质选择恰当形状、描边或裁切并形成系列。形状数量服从构图和主题，主体不得被误裁。
- [ ] **对齐 + 间距规整(align,见 §9⑯⑱ / `⚠ VBALANCE`)**:同页元素共对齐轴(共左线 / 顶对齐 / 基线 / 数字右对齐)、间距走 `--space-*` 阶梯且同级等距、重心在安全区居中或撑满;眯眼看没有"歪着 / 空一条 / 参差不齐"的别扭。

〔单背景模式下的"节奏"= 同一模式内靠明度 / 密度变体拉开,而非亮暗背景互跳。〕

## 怎么用(各角色对照)

- **Slide Group**(`subagents/slide.md`):由同一个 Agent 按页序串行完成“单页首稿 → 单页渲染 → 单页 Vision → 必要修复复验”，当前页 ready 后才进入下一页；组末再用整组批量渲染检查亲缘性与变化。组末总览不能替代任何负责页面的单页像素自检。
- **review subagent**(`subagents/review.md`):通过全册概览 + 自适应分组联系表覆盖所有页面,同时过「单页检查」与「整套检查」；一次建立问题账本,直接合并修复视觉问题,重渲变化页并用复验联系表看新像素。单次 Review 不反复清告警；有证据的硬伤交回原页组后，才允许新的 Review 复验，任务总计最多 3 次。
- **编排器**:规划期就用「单页检查·表达与内容逻辑」「整套检查·全篇结构」自检叙事与内容(规划期堵掉比渲染后返工便宜)；Review blocked 后只按证据重派原页组，最多返修 2 次。达到预算后恢复最后验证版并带 warnings 交付可用成稿，不把 advisory 或收尾文本问题判成整项失败。
