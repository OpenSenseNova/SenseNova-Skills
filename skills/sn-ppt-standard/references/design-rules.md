## §T1 · 视觉密度总纲(正交轴,统辖 §1/§2/§6/§8;别用「克制/丰富」单轴思考)

**视觉密度 = 两个正交轴的乘积,分开判、别搅在一起:**

- **轴1 · 语气(收敛度)← 由「受众 × 场合正式度」定**
  - 收敛:党政 / 学术 / 法律 / 医疗 / 报告 / 科研 —— 受众要庄重、题旨要可信。
  - 表达:漫画 / 电影 / 文旅 / 庆典 / 发布会 / 杂志 / 封面 —— 可尽情丰富。
  - **按受众定、不是见「学术」标签就机械收**;字体也**跟场合正式度走、不跟题材走**(题目哪怕是科技/数据,场合党政庄重就用直立宋体,别反射式切「技术→得意黑」→ 否则党政 deck 长成科技发布会)。
- **轴2 · 前景视觉量(充实度)← 由「内容需要多少视觉承载」定,与轴1 无关**
  - 机制/结构页要概念图(§概念图硬门**不因克制豁免**)、数据页要图表、封面/章节/hero 要主视觉 —— **任何语气下都不能塌到 0**。

**推论(把「讲 5 遍」压成两句):**
- **「收敛」只压**【装饰 / 字体数 / 大字力度 / 氛围堆料 / accent 面积】,**绝不压**【前景内容视觉量:概念图 / 图表 / 图标 / 母题 / 克制的真实配图】。
- **病态 = 把「收敛」做成通篇纯文字 + 秃细线框 + 空底**(贫瘠 ≠ 克制;`⚠ SPARSE` 填充不足多半是这个根)。目标是**克制的丰富**,不是贫瘠。

> 下面 §1(背景色彩「克制≠光秃/太素」)、§2(字体收敛)、§6(背景「有背景≠堆氛围图」「别读成少放视觉」)都是这条总纲在具体维度的落地;读到那些「克制但别秃」的补充时,回到本总纲的两轴判据即可,别当成互相打架的独立规则。

**「高级 / 有设计感」= 可操作的 8 条,不是玄学(自检拿这 8 条对,不是「感觉高不高级」):** ①**准确的比例**(元素尺寸/间距成比例关系,不是随手估);②**清楚的视觉层级**(一眼看出主→次→辅,字号/字重/色 3 维拉开);③**稳定的重心**(内容在安全区居中或有意偏置,不飘不偏,`⚠ VBALANCE`);④**克制且有语义的用色**(主色统治，accent 只服务真正重点，不按固定色数机械裁剪);⑤**有判断的裁切**(图/字的裁切是设计决定,不是被容器逼的);⑥**字与图的关系**(排版是构图的一部分、不是给图配的说明,见 §8.5 编辑动作);⑦**细节集中在局部**(复杂细节聚一处、其余安静留白,别整页平均用力);⑧**像品牌/展览/出版物,不像模板**(有一个贯穿的设计概念+母题)。**"高级"不靠黑金/贵材质**——靠这 8 条的执行度。缺哪条补哪条,别用"加装饰/加颜色"冒充高级。

## 1 · 背景与色彩

- **⛔ 别默认奶油 / 米黄 / 暖白底(最泛滥的雷同底色)。** 动笔先问「这主题最该是什么底」,让背景跟风格 + 色调走:商务 / 科技 / 数据 / 金融 / 政务 / 奢侈 / 暗黑极简 / 赛博 → **深底**;医疗 / 科研 / 法律 / 冷调 → 冷白蓝 / 冷灰;高对比 / 包豪斯 / 杂志 → 纯白或纯黑。暖白只留给真正偏暖的(生活 / 文教 / 手作 / 婚庆 / 母婴 / 餐饮),其它主题用暖白要有明确理由。
- **★党政 / 党建 / 理论学习 / 政务汇报 = 庄重靠「排版秩序」,不靠戏剧化暗底 / 氛围堆料。** 底三选一:**浅暖中性 / 象牙白**(配直立衬线 + 红金 + 党徽母题——和廉价米黄纸感的差别在**衬线气质 + 红金克制 + 秩序**,不是纸纹)、**正白 + 正红**、或**深红 / 绛红底**(党的正色)。**★别用近黑 keynote 暗底**——「近黑 + 斜切大数字 + 低对比氛围图」= 一眼科技发布会 / 运动励志,党政庄重感全丢。字:**思源宋体(`--font-serif`)直立**当展示 + 标题,**禁得意黑 / 斜切 / 斜体展示字**(俏皮出戏)。红金只作**克制点缀**(党徽 / 星标母题、细红线、金勾边),**别堆满幅氛围图 / glow / 渐变**——庄重来自**衬线 + 留白 + 秩序 + 高对比**。**★但「克制」≠「光秃」**(见视觉密度总纲 T1):党政 deck 照样要**丰富的前景视觉**——机制 / 结构页给 Canvas / 图片概念图解(§5 硬门不因克制豁免)、数据页给图表、要点配图标 / 党徽 / 星标 / 绶带母题、合适处放克制的真实配图(实景 / 文献 / 场景,调进红金)。**别把「克制」做成纯文字 / 纯细线框墙。**
- **全套建立一个背景系统，而不是每页只铺同一块底色。**先判断场景：学术、组会、合规、严肃评审等可以用更安静的基础画布；产品、品牌、招商、文旅、文化、故事、课程导入、活动与大众传播等表达型场景，默认应主动考虑环境层，而不是整册同一纯色底。先锁定一个基础明暗家族，再从同色阶纯色、定向渐变、克制色块、主题环境光、低对比颗粒/网点/纸纹、主题线性纹样和图片底里选择少量相容手法；内容页轻、峰值页和特殊页可更强。变化必须继承同一色彩故事与图形语法，不能一页一套滤镜，也不要把所有题材都做成深藏青。
- **写一句贴主题的「色彩故事」**(如「档案纸暖白 + 墨黑 + 一味赭石」「深松石绿 + 沙色」)记进 `plan/deck.md`,`base.css` 照它定 token。
- **⛔ 默认禁两套 AI 默认色**:① **深藏青 + 霓虹青 / 电光蓝**——暗底选带明确色温的深色(暖炭 / 墨绿蓝 / 深普蓝 / 深褐 / 深墨绿),`--accent` 降饱和(≤~60%,避开 180–195° 霓虹青 / 电光蓝做主强调),不要 `#6366f1` 靛蓝;② **深色 + 琥珀金 / 暖金**(做数据 / 商务 deck 时)——色彩故事从主题派生非金(暖纸白+墨+绛红 / 冷石板灰+暖白+钢蓝 / 深松绿+沙 / 深酒红+骨白);真要暖金,得主题本身金属 / 奢侈 / 能源,且全套只此一味。
- **强调色要「配给」、有主次**:accent 只用在真正要喊的内容（头条数字、关键系列、核心节点），别把标题装饰线、眉签、每个 KPI 和每根柱都平均染色（**到处强调 = 没有强调**）。图表系列可走中性灰或同色系浓淡，让真正的结论成为最强 accent。单 accent 还是双 accent 由页面重心决定，不按元素个数机械判罚，也别因怕 slop 而通篇单色寡淡。**克制 accent ≠ 配色太素**：用主色深浅和邻近色建立层次，让头条最强、次级递降。
- **四层调色板(量化)**:中性层 70–90% 像素 · accent 层 ~5–15%(1–2 个,双 accent 一冷一暖如 `#002FA7`+`#E53935`,别 3+ 彩虹)· 语义色 0–5% · 效果层由你决策。**对比度是门 → 见 §T2。** **暗底别用纯黑纯白**(`#0f0f0f` 别 `#000`,`#fafafa` 别 `#fff`;暗底描边用半透明白)。**有主题色彩故事的渐变**(藏青→橙暮色)可用于 hero / 大色块;避开无主题的「通用信任渐变」(紫→蓝 / 靛→粉)那种 AI 味。
- **色块收敛 + 改色有逻辑**:关键不在数量，而在**换颜色必须承载含义**——标出重点、区分类别或表示状态，不是为了「花」而换。同一类块使用同一颜色角色；若多个色块平均争抢注意力，就合并层级或收回同色系，而不是机械数块。
- **面板靠色调分层出体积**(页底→面板→面板内三级各差 ≥4% 明度):暗底面板 = 4–6% 白填充 + 8–12% 白描边;亮底面板 = 1–2% 墨填充 + 6–10% 墨描边。不要硬投影，也不要在每个标题后反射式摆同一个圆形径向光斑假装景深。**有主题的环境光可以用**：它应能说清光源或隐喻（舞台灯、日出、热源、霓虹、窗光等），位置与主视觉/阅读方向相关，通常非对称、低对比，并在文字区收敛。解释不了来源和构图作用的 glow 仍是 fake 光晕；更足的主题气氛可用 §6 的背景肌理、氛围图或生成背景。
- **调色板封闭**:任何颜色(含状态色)都必须来自 `base.css` 且与主色调和,不是直觉的大红大绿大粉。**硬规:`--up` ≠ `--warn`;涨跌一律「颜色深浅 + 箭头 / 正负号」双通道,别只靠色相**;免责 / 提示条用主色淡色调,不要粉不要红(⛔ 金色 deck 里冒出 `#FBEFEF` 粉底或鲜红 `-12.5%` = 出界)。

## §T2 · 对比度 gate(唯一量化定义处;§1/§10/§9⑦ 与 render.py `⚠ CONTRAST` 都只引用这条)

- **对比度当 gate(是门不是目标)**:正文对底 **≥4.5:1**;大字(>18px 或 14px 粗)/ 大号 UI **≥3:1**。主色压浅底发虚时,**text 用途换到更深一档(600 级)**、亮色只留作填充。
- **暗底 / 图片底是重灾区(matq5k 39-deck 头号毛病)**:暗底禁深灰 / 深棕 / 暗金小字 → 改高亮白 / 亮米 / 主题色;图片底文字见 §T3托住。
- **机核**:`render.py` 的 `⚠ CONTRAST`(实心背景 WCAG 实测,正文 <4.5 / 大字 <3.0 命中)是这条的自动门;命中即当硬伤按本条修。

## §T3 · 图上文字(唯一定义处;文字压图/图形上是好设计,放心用)

文字叠在插画 / 照片 / Canvas 图形 / 满铺背景上时——**是好设计、别因怕遮挡而回避**,方法你自主,要用就保证读得住:

- ① **Canvas 只画几何，准确文字优先放 HTML 覆盖层**；若必须在 Canvas 内画字，最后绘制并确保高 DPI 与对比。
- ② 给文字加 **`paint-order:stroke` + 与底同色的浅描边**,或用现成 `.scrim--t/b/l`(或 `.scrim--light`)**定向压一侧**、或给那行加 `.text-plate` **局部托板** —— **是局部退让、不是全局压暗**(保留主体 / 氛围;别为保险牺牲照片氛围)。
- 文字在角落时使用模板的 `.scrim--tl/tr/bl/br`：它们仍覆盖全画布，只在角落径向渐退。禁止自建有固定宽高、边缘仍不透明的黑色 scrim 矩形；那会在图片上留下明显横线/黑带，不是“层次”。
- ③ HTML 层装饰绝对元素给 `pointer-events:none` 且 z-index 低于同区文字。
- 这根治「插画 / 背景上的小字被线条 / 高频细节吃掉」与图元互相遮挡。
- **机核**:`render.py` 的 `⚠ ON-IMG-NOSCRIM`(文字压图 / 满铺底但无 scrim/托板声明)是这条的提示门 —— 命中就按本条垫 scrim/托板/描边。**有意的层叠**给容器声明 `overlay`/`scrim`/`decor`/`overlap-ok` 类或压到低透明度即豁免。

## 2 · 字体与排版

- **★展示体 / 毛笔 / 书法字的辨识度问题 → 就地修,别换掉字体家族**:展示体 / 毛笔 / 书法大字出现辨识问题(笔画粘连、斜杠与数字粘住、字距过挤)时,**就地微调**——加字距 / 给斜杠 · 连字符等符号留 ≥0.15em 间距 / 换那个符号的写法 / 微调字重,**别把整块毛笔 / 展示字降级成宋体或 sans**。既定美术风(尤其文旅的毛笔 hero、封面的书法主标题)是刻意选型,为一个局部辨识问题牺牲掉整页调性不划算——修的是那个局部,不是换字体。
- **★展示大字要克制、且不挤压下方 / 不压页脚**(大字尺度总则见 §3(T4)):hero 大数字 / 巨字标题 / 大序号字**字号有节制**——大到成为焦点即可,别大到把下方正文挤得贴页脚、或压住相邻行 / 页脚带;定高 hero 区四周留 safe padding,底部末行与页脚带之间留呼吸(**页脚是保留带、不许被内容压**,详见 §底部安全区)。
- **中文字体必须显式命名**:中文 deck 的正文 / 标题 `font-family` 必须带 `"Noto Sans SC"`(或 `"Noto Serif SC"`),否则拉丁展示体缺少中文字形时可能渲成豆腐块(□□□)。页面只写 `--font-*` 角色 token，不依赖 CDN 或未登记的本机字体；`deck.py prepare` 会从 OFL 白名单选择实际可用字体、前置字符子集并注入 deck-local `@font-face`，交付时随包携带许可证。未命中白名单的本机字体必须回退到已批准的中文字体。详细许可和角色映射见 `references/fonts.md`。
- **全册字体家族 ≤ 3 且统一,别每页换花样**:整册跨全部页面最多 3 个字体家族(典型:中文标题/正文一族 + 拉丁/数字一族 + 至多 1 个合题点缀族),同一角色每页都用同一家族;严谨型收敛到 1–2 族。角色多不等于句内混搭:每个角色必须跨页稳定、同一句中文仍只用一个家族。正文 / 表格 / 图表标注 / 页脚 / 眉签用 `--font-sans`;Hero/KPI/章节号按 Style Lock 选择 `--font-number`;**中文绝不用 `--font-mono`**(无中文字形→回退卡通体),`--font-mono` 只服务纯拉丁代码、坐标和 ID。现代编辑 / 实验性主题可让 Unbounded / Syne 承担拉丁展示、Archivo 承担数字和标签、Noto Sans SC 承担中文与正文;文旅、人文、漫画等再从 `references/fonts.md` 选择合题声部。
- **同句不混族**：一句中文标题、结论、按钮或标签内部使用同一字体家族；强调词只改颜色、字重、字号或装饰线。禁止把半句黑体和半句卡通/手写体拼在一起。表达型字体必须有合题语义，并通过 `.is-expressive-type` / `data-type-intent="expressive"` 显式声明。
- **中文标签不套拉丁排版**：中文眉签、部门名、页脚、来源和短标签用 `--font-sans` / `--font-serif`，字距默认 `0–0.03em`、不得超过 `0.08em`；不使用 `--font-mono`、`--tracking-caps` 或 `text-transform:uppercase`。纯拉丁 ALL CAPS、API、代码、坐标和真实编号才使用 `.is-latin-label` / `.is-tech-id`。
- **★字体跟「场合正式度」走、不跟「题材」走**(视觉密度总纲 T1 轴1 的字体落地):党政 / 政务 / 理论学习 / 法律等庄重场合 → `--font-serif` 思源宋体**直立**当展示 + 标题,禁得意黑 / 斜体 / 斜切展示字。题目哪怕是科技 / 数据(如「新质生产力」),只要场合党政庄重,就用直立宋体、别反射式切「技术 → 得意黑」(否则党政 deck 会长成科技发布会)。
- **★克制 / 严谨场合反过来要「收」**(同 T1 轴1;治「严谨汇报也堆 4–5 种字体 + 印章赭红等点缀」)——这类是「多字体丰富」的反面,按**受众与题旨的正式度**定(学术 / 科研 / 报告 / 法律 / 政务 / 医疗;按受众定、不见「学术」标签就机械收):
  - **字体收敛统一**:全套 ideally **1 个衬线**(标题 + 正文,或衬线标题 + 无衬正文)+ **1 个无衬**(标签 / 数据)+ mono **仅**用于真代码 / 数据表;**别同屏堆「得意黑封面标题 + 斜体衬线英文副题 + mono 眉签 + 宋体正文」4–5 种**,统一到 **2–3 种**,层次靠**字号 / 字重 / 字距**拉开、别靠换字体。**这类 deck:风格统一 > 丰富度。**
  - **减不必要的装饰**:严谨感靠**排版秩序 + 留白 + 层级**立,**不靠装饰点缀**——别放装饰性印章 / 图章 / seal / stamp / 徽标、多余色块 / 线框母题;accent 收到极简(≤1 处细规则线或一个眉签色,甚至可无)。「一味印章赭红点睛」在生活 / 文旅是味道,在学术 / 报告里 = 过度设计。
  - ⚠️ 收敛只压字体数 / 装饰,**不压前景视觉量**(见 T1):严谨 deck 照样要概念图 / 图表 / 克制配图。
- **编辑级排版精修(量化硬规以本节为准)**:display ≥48px 带负字距 `-0.02~-0.03em`;ALL CAPS 必带字距 `0.06–0.1em`(中文不用 uppercase);正文测量 50–75ch + 慷慨行高 + 右侧 ragged(不 justify);pull-quote 是排版打断(无卡片 / 边框 / 底色,靠尺度 28–40px + 留白);display 与副题落差 ≥1.5×;正文加粗每 ~400 字 ≤2 处。**禁「1–2 字寡行 / 孤行」**:`.slide-title` 已 `text-wrap:balance`、正文已 `text-wrap:pretty`,标题仍可手动 `<br>` 断得每行都'满';数字 + 单位、专名 / 术语 / **地名 / 人名 / 机构名**(如「黑龙江」绝不断成「黑龙 / 江」)用 `white-space:nowrap` 不拆行。
- **★底部安全区 + 单页密度上限(治「内容压到页脚 / 下方遮盖」)**:`.slide-body` 与 `.slide-footer` / 页码之间留**硬安全带**,**正文绝不许溢出压到页脚 / 页码带**;一页内容量以「**舒适间距下放得下**」为准——放不下就**减字 / 拆两页 / 换更紧凑版式**(多项要点用 `.arch-*` 的 2×2 卡片,别用「N 项纵向长流水 + 每项整段正文」硬堆到爆)。**出处只写一次**:每项已内联出处就别再来一条底部汇总 source line(或反之)。render.py 的溢出 / 碰撞检查会把「正文压页脚」判失败。**★底部满幅 / 半幅图 + 手写批注 / 金句同样归这条管**(治「下方遮盖」——渲染门抓不到「页脚压在照片上」:text↔图不算 text↔text 碰撞、是盲区,必须你自己守):① 底部照片在**页脚 / 页码带上方收住**、留干净安全带;② 若照片满铺到底(`.slide--bleed`),页脚 / 页码**必须坐在 scrim / 托板上或用足对比色**(见 §T3 T3),别深字直接压深图糊成一团;③ 手写批注 / 金句别钉在页面最底边和页脚挤一起;④ 或该页干脆按满图页处理、豁免页脚家具(`.slide--cover`)。
- **标点跟着语言走：**中文屏显文案优先使用中文标点，英文短语使用英文标点；数字、代码、单位、日期、百分比、文件名和纯英文缩写照原样。它是文案润色原则，不是像素硬门：页面已经清晰成立时，不为全册标点机械归一化启动修复，更不得用全局正则改 HTML/CSS/属性引号。确有明显观感问题时，只对可见文本节点做小范围精确 patch。
- **文字精炼**:用短语不用整段——1600×900 装不下密集长文,会溢出。

## 3 · 大字与 hero(T4 —— 唯一定义处;★大胆是默认)

**大字 + 大尺度对比是「设计感更强」的主杠杆——大胆用。** 锚点页 / 关键数字 / 封面 / hero 尺度 **3–4×** 拉开,别一味停显得寡淡;display÷副题 ≥1.5×。**字重按「设计读数」的美学家族选、别写死**:冲击 / 展示类用 **700–900 黑体**;编辑 / 奢华 / 静类可用 **300–400 细字重**做优雅落差。**唯一地板 = 投影可读**(display 字重别 <300、正文别缩)。**同屏字重 ≤2 种**,强调用同族 italic / bold,**别往 sans 标题里塞一个花体字**(混族强调 = 业余)。

- **在真正的叙事高点建立视觉峰值**，可以是 `arch-hero-stat`、满幅金句、单一主视觉、关键机制图或结论对比。短小、克制或严谨型 deck 不必硬凑巨字 hero，但不能全册没有重心变化。
- **封面 / 结束页 = 一个统治性焦点 + 大留白**:用 `.slide--cover`,排一个巨字标题 or 满图主视觉当**唯一重心**,**不放页脚 / 页码**(正文页家具落到封面 = 一眼廉价);也不放 `SCENE / COVER / END`、虚构档案号、制作状态、总页数/时长等运行标记。标题上方气口别过多(≤ 一个 `--space-section`)。**纯文字封面 = 未完成**——封面要有真实视觉资产(满图 / 巨字母题 / 主视觉),别文字 + 渐变糊;**「大而空」的封面**(巨标题占满却无焦点内容)也不是设计、是廉价。层级靠字号、字重、图像、色场与留白拉开，不靠伪元数据、重复标签、边框或阴影撑。
- **★过渡页共享系统，不复制死模板**：所有章节分隔页共享字体角色、章节编号语法、标题锚点家族、色彩/图像处理和图形语法；允许在同一系统内改变左右重心、裁切、色场方向或主视觉状态。别出现「这一页宋体、下一页黑体」「这一页重复两个 02、下一页没有章节标记」等语义和字体漂移，也别只换章节名就机械复印。章节页要么每章都给、要么整册都不用；封面、目录、章节与结尾应有可辨认的视觉亲缘性。
- **★过渡页简洁，但不能松散空壳**：章节号、章节名和一句转场承诺应形成一个有张力的主信息团，再由满幅/半幅图片、主题母题、色场、裁切或超大排印形成视觉对重。留白必须把视线推向焦点、建立方向或制造章节换场；若文字缩在一角或一条窄带、其余区域只是未参与构图的纯底，即使没有溢出也未完成。修法是放大和重组主信息、改变图文比例或让视觉资产进入构图，不是给章节页塞正文、卡片和方法清单。
- **唯一护栏:别几乎每一页都堆巨字**——那不是 hero、是没有重心;给巨字留几个真高点、其余页安静即可。**几页大胆、几页安静由你按叙事高点定,不设死数上限。**
- **大字要「大得有理」——落网格、带标签、按 register 定大小(治「大字突兀」)**:放大字突兀几乎都是——① 它**脱离页面对齐轴孤零飘着**(不与同页元素共左线 / 共基线、旁边没有紧贴标签说清它是什么);② 它的**尺度和这页 register 打架**(克制学术页里塞 360px 尖叫数字);③ 它**没落在垂直重心上**(把版面推得偏上 / 偏下、留一条无理由空带——即「大字位置奇怪、上下留白」,`render.py` `⚠ VBALANCE` 会点)。修法:大字**必须落在页面对齐轴上**、**带紧邻标签**(这数字是谁、比什么、单位)、**大小随 register 走**(表达型可顶天立地;克制型放大到「一眼是这页重心」即可、别炸)、所在块在安全区**视觉居中或撑满**。
- **学术 / 报告等克制型 deck 的记忆点要「稳」不要「炸」**：适度放大的关键读数、说清机制的概念图或结论行加重的对比表，都可以形成视觉高点。**宁可不放，也别硬凑一个和气质打架的大字**。
- **偏移复制的「套印错位 / 重影」只配单行或隔开的文字,别叠在紧排多行巨字上(治多行 hero 上下糊成一团)**:大字 hero 用 `::before`/`::after` 做偏移复制的第二层(riso 双色套印、故障重影、offset ghost)时,**上一行的重影 + 得意黑 / 斜体展示字远超行盒的下伸墨迹会一并糊进下一行**——两行的**行盒看着没重叠、墨迹与重影却已相撞**(且这种行内 text↔text 重叠是渲染门盲区、抓不到)。① **带偏移重影的 hero 优先单行**;② 必须多行则**行距开足**(得意黑 / 斜体展示字多行 hero 行距给到 ~1.5、且每行重影收在本行内)**或把偏移压到 2–3px 的极细套印**(而不是靠大偏移刷存在感);③ 反过来:关掉重影后若仍撞,才是纯字号 / 行距问题,按上一条大字规则处理。正文与图表标注不套偏移重影;Hero 数字可用本册 `--font-number`,但仍守同样的墨迹安全区。
- **自检**:grep `arch-hero-stat` / `arch-quote` / 巨字 / full-bleed——命中 0 = 无 hero,补一页;命中到「几乎每页」= 收几张回安静版式。

## 4 · 图表(ECharts)

- **数据图表用 ECharts 手写**,整套配色(系列 / 坐标轴 / 网格 / 文字 / 标注)全取自 `base.css` token——多系列从 `--series-1…6` 用 JS `getComputedStyle` 读**直接色值**(别把 `var()`/`color-mix()` 喂 ECharts,它解析不了),不够就基于主色派生;**绝不用 ECharts 默认调色板或调色板外颜色**;容器给显式宽高。HTML 统一引用 Deck 自带的 `../assets/vendor/echarts.min.js`；`deck.py prepare` 会前置准备该文件，`build` 会再次规范路径并校验交付依赖。不要引用 CDN、Skill 目录或工作区外路径。图没实际生成 Canvas/SVG 按硬伤处理。
- **图表即新闻图**:页标题优先写**结论**而不是泛题目；直接在数据上标关键值，数据项较少且已直标时可精简数值轴和网格线，线图系列名可标在线尾。图例与注释只保留理解所需内容，callout 不压数据线/柱、不互相重叠，整套共用一套注释体例。
- **★ECharts 标签防遮盖(治图表 label 严重重叠,硬门)**:一律开内建防叠——`xAxis`/`yAxis` 的 `axisLabel:{ hideOverlap:true }` + `grid:{ containLabel:true }`;数据标签 `series[].labelLayout:{ hideOverlap:true }`;**折线用 `endLabel` 把系列名 / 末值标在线尾**、别每点打标签也别堆顶部图例;**该有刻度就出刻度**;两系列在某点数值重合就**只标一次或上下 `offset` 错开**。
- **数字体例统一**:同指标族用同单位 / 精度 / 范围写法(别一页混 亿 / 万亿 / B / T / M),范围用统一连接号(`2,790–6,382 亿`),估算 / 预测同一标记,一行数字小数对齐。**KPI 大数字要有层级**:一排里只让一个当头条(最大 + accent),其余次级;每个数字给「值 + 一句上下文 + 同比(▲+80%)」,来源压页脚一行。
- **★数学 / 符号排版要对**:**乘号用 `×`**(U+00D7)且两数之间**垂直居中**,别用字母 `x` 或 `*`;**幂次 / 上下标用真上标**(`<sup>`/`<sub>` 或 `vertical-align`);**运算符 / 单位贴数字位置要准**——`−`(减/负号,别用连字符 `-`)、`%`、`‰`、`±`、区间连接号 `–` 各就各位;正负号、货币号、单位紧跟数字不断开。
- **★数据页有天然焦点数时,放大它作「hero 读数」**(你判断、非每页必须;尺度总则见 §3(T4)):图 / 表 / 树里**最重要的那一个**数字 / 行 / 节点放大到 display 量级(≥2× 正文 + `--accent` + 负字距),其余降中性灰(`--ink-dim`)退让。**⚠️ 放大要落在图 / 表本体里、不是只在标题**:ECharts 用 `rich`/`label` 把那**一个**关键数值标签放大(≥1.8–2× 邻近标签 + `--accent`),表格把制胜格的**数字本身**放大(≥1.8× 邻格)。**纯趋势 / 结构 / 多指标并列图没有单一焦点数,就别硬凑大字**。
- **一页围绕一个主要分析任务。** 通常用一个主图最清楚；确需并置的小图必须共同回答同一问题、层级明确，若与密集数字和长文争抢注意力就拆页。
- **数据页版式别都一个样**(治「大数字左 + 图表右」机械连用)：根据发现选择纯图表满版、大数字 hero、对比表、左图右文、时间轴或排序条；出现连续同构且没有叙事理由时再换结构，不按固定页数配额判断。
- **示意 vs 真实分清**:一张图别把「示意 / 插值」和有源真值混着不区分——要么整图标「示意」、要么只画有源真值。**图配数据**:近似份额别用饼 / 环(看不出差)用排序条,示意数据别画成带精确小数的饼图。

## 5 · 概念图与大型示意图(Canvas / 图片优先)

- **结构 / 机制 / 关系 / 流程 / 架构 / 层级页必须图解，但默认不用大型 SVG。**先判断表达是否需要精确结构：
  - 需要精确节点、连线、比例或动态布局 → 用 Canvas 绘制几何，准确文字放 HTML 层；
  - 更重视场景、隐喻、空间感或视觉冲击 → 用真实/生成图片承载画面，准确文字放 HTML 层；
  - 数据关系 → 用 ECharts；
  - SVG 只用于 icon、logo、箭头、标记和小装饰。
- **默认禁用半屏/全屏手写 SVG 概念图。**只有用户明确要求矢量交付、必须复用用户提供的准确矢量资产，或元素本身就是小型 icon/logo 时例外。
- **Canvas + HTML 标签规则：**Canvas 只画线、面、节点、路径和强调；标签、数字、来源用 HTML 覆盖层排版。Canvas 显式设置内部像素尺寸与 CSS 尺寸，按 devicePixelRatio 缩放；颜色从 base.css token 读取；字体 ready 后绘制；禁止把关键文字烘进 Canvas 导致模糊或无法精确排版。
- **图片 + HTML 标签规则：**生成图 prompt 默认 no text；让图片承担场景/质感/隐喻，HTML 承担标题、节点名和数值。图片不得伪造数据图表。
- **场景硬门：**分析、机制、结构、层级和流程页不能退化成纯文字或等权卡片墙。选择 matrix、flow、comparison、Canvas diagram 或 media-led diagram，且一图只讲一个关系、节点通常 ≤7、方向明确、标签不碰线。
- **先验收语义，再验收造型：**图必须兑现逐页计划的“视觉验收”。标题、图例、节点和结论使用同一语义；表达传递、因果、顺序或反馈的线必须有明确方向和端点，装饰虚线/弧线不能冒充关系。
- **领域图不能泛化成占位符：**科学、技术、医疗、工业和方法说明优先使用真实或忠实简化的领域对象/输出（光谱、显微图、CT 截面、样本、仪器状态、检测结果等）。通用圆/矩形/六边形只适合抽象层级；若看图仍无法知道这是哪个领域或方法，换成具体证据视觉。
- **体量与清晰度：**大型示意图应占正文区主要面积；文字层 ≥ `--fs-min`，节点等距、连线接锚点、标签有留白。图太小、主次不清或文字碰线均为硬伤。
- **反 slop：**禁止发光粒子网、节点星座、无意义连线壁纸；只有主题确为网络/图谱且关系真实时才使用网络结构。

## 6 · 配图 + 背景氛围(封面 / 章节 / hero **默认应有**主视觉;正文别通篇纯色底发单调——都以服务主题 + 文字可读为准)

**配图策略(用多少、放哪、真图还是生成、要不要背景 / 氛围图)由你自主决定**,不再一律克制。判据不是「装饰 vs 内容」一刀切,而是**这张图有没有在为这页的主题 / 情绪 / 说服力服务**。

- **★媒介由「内容是什么」定、语气由「受众 / 场合」定——别拿题材标签一刀切**(这就是 T1 两轴在配图上的落地):选**照片 / Canvas·图片概念图 / 图表**只看这页**内容本身**——身份要紧的真实主体 → 真照片、机制 / 关系 / 结构 / 流程 → Canvas 或图片概念图、数据 → 图表。而**克制 vs 表达**(字体数 / 大字力度 / 装饰多少)才随受众与场合的正式度走。两者别混:一个 deck 是「学术 / 政务」影响的是**语气该收敛**,**绝不等于「必须用图解、不能有照片」**(学术里有真实影像 / 实景 / 人物 / 作品就照样上真图)。题材只是**常见相关性**、是内容驱动的**结果、不是判据**。
- **✅ 封面 / 章节分隔 / hero 页默认就该有主视觉或满幅氛围背景**(纯色底的封面 / 章节 / hero = 单调、多半「未完成」):真图由父级通过支持图片检索的 canonical `web_search` 或 `serper_images.py` 搜索并下载，生成图由父级调用 canonical `generate_image`，全部落到 `$DECK_DIR/assets/` 并登记来源——**前提三条**:① 服务这页的主题 / 情绪、② 进整套调色板(同媒介 / 同处理)、③ **文字压得住**(方法见 §T3 T3:定向 scrim / 局部托板 / 描边,不强制整图压暗)。**★封面 / 章节分隔 / hero 这三类要「各自」都给,别只把封面配了图就算数**——**章节分隔页最常被漏**(只放大标题 + 一个淡序号水印 = 还是纯色单调、不算氛围):章节页也要一张满幅 / 半幅氛围图或强主题母题背景,和封面同一视觉配方成系列。
- **★但「有背景」≠「堆氛围图」——克制、协调、对比优先(治「背景丑 / 对比乱 / 全册乱晃」)**:满幅氛围**只在能做得好看时才用**——① **宁可干净的纯色 / 极简母题底,也不要 busy、低对比、浑浊、跑调的满幅氛围图**;② **全册一套背景配方**(一种处理 + 一种母题 + 一套配色)贯穿到底,别每页各生各的图;③ **对比 / 配色纪律管到装饰元素**(见 §T2):圆环 / 连线 / 英文标签 / 母题也要够对比——别 maroon 圆叠近黑几乎看不见、别低对比 gold 文字；色块和 accent 都必须承担明确层级，不按固定数量机械裁剪;④ 禁的是**无主题、反射式复用的 glow / 径向渐变假景深**，不是所有环境光；有明确光源、主题隐喻与构图方向的低对比光场可用;⑤ 庄重题材(党政 / 政务 / 学术 / 法律)优先干净底 + 排版秩序(见 §1 党政条)。**一句话:协调 + 克制 + 对比 > 有没有氛围图**。⑥ **⚠️ 但别把这条读成「少放视觉」**(见 T1 视觉密度总纲)——克制冲着**丑 / busy / 跑调 / 装饰过度**去,**不是冲着视觉元素数量**:干净底上照样要足量前景视觉(概念图解 / 数据可视化 / 图标 / 母题 / 克制真实配图),`<img>` + `<canvas>`/CSS 图解 + 图表全 deck 别塌到接近 0。目标 = **克制的丰富**,不是贫瘠；`SPARSE` 只提示检查留白职责，不是自动补元素的阈值。
- **✅ 正文页也别通篇纯色板——可用贴主题的环境光、背景肌理、母题或图片托底出气氛(治「背景太单调」)**:低对比的**主题相关**背景元素——舞台/窗光/夕照等有方向的环境光、蓝图网格(工程)、等高线 / 地形(地理)、纸纹 / 档案肌理(报告 / 政务)、星图 / 电路 / 数据流(科技)、水印母题(品牌)，以及局部或满幅图片背景；生成位图或 CSS 绘制皆可，**全套共享同一处理家族、进入调色板**。图片背景不只属于封面：当它提供场景、情绪、空间或识别价值时，普通内容页也可使用 full-bleed、图字分屏或局部裁切。**三条护栏**:① 低对比托底或使用定向 scrim，不能压过正文对比 gate、② 贴主题且参与焦点/方向、③ 文字区保持干净。无主题 fake glow 仍禁；主题环境光和真实/生成的场景背景可用、鼓励。
- **仍避开「空转 slop」**(不是避开背景图本身):和主题无关的随机抽象渐变 / 泛用「科技感」/ 无意义情绪图 / 会糊掉文字的花底——仍不要。**纯图标 / 分隔线走 CSS 或小 SVG，数据图走 ECharts，大型概念结构走 Canvas 或图片 + HTML 标签**(那是结构不是配图,不用 `generate_image`)。
- **别把“避免 AI 味”误写成“避免图片”。**AI slop 来自无主题的视觉套路、错误主体、廉价 glow 和千篇一律的蓝紫配色，不来自照片或生成图本身。图片能提供真实证据、主体识别、空间氛围、人物情绪或故事锚点时，应优先把它纳入构图；统一感靠选图、裁切、色罩、颗粒与留白体系建立，而不是把图片全部删掉。
- **⛔ 禁 hotlink 外部图床直链**(unsplash / placehold.co / picsum / placekitten… 的 URL 直接写进 HTML):远程直链易 404 / 防盗链裂图,deck 必须自包含;占位图(灰块 / lorem 图)= 占位 ≠ 内容,一律不用。**「禁 hotlink」≠「禁真图」**——真图不是不能用,是不能直接外链。
- **真图 vs 生成——按主体分流**:具体、身份要紧的真实主体(真实地点 / 人物 / 事件 / 实景 / 建筑立面 / 产品)→ **取真图**:父级用支持图片检索的 canonical `web_search` 或 `python "$SKILL_ROOT/scripts/serper_images.py" search` 查找候选，再用 `python "$SKILL_ROOT/scripts/serper_images.py" fetch` 校验并下载到 `$DECK_DIR/assets/`，同时登记原始 URL；风格化 / 插画 / 概念 / 抽象 / 氛围 / 泛化场景、及要求统一画风的成套主视觉 → **父级调用 canonical `generate_image` 生成到 `$DECK_DIR/assets/` 并登记 prompt、模型与来源**。真图落地后先保留主体具有识别或证据意义的颜色，再用裁切、背景、轻量色温、局部色罩或边框调和进主色。整图灰阶 / duotone 只在用户明确要求，或视觉主张确实依赖它且不损害辨认与教学信息时使用；不要把“学术、高级、统一”自动翻译成 `grayscale(1)`。
- **✅ 承载内容的照片该配就配(别过度克制)**:照片本身是内容时——真实场景 / 建筑立面 / 实物 / 作品 / 人物 / 案例画面 / brief 点名的真实图像——就配,比纯排版更有说服力。**尤其招商 / 地产 / place / 产品 / 人物 / 真实事件 / 实景类 deck 至少 1 张真实立面 / 主体照片**;科普 / 科研里 brief 点名的真实照片(如 EHT 黑洞照)必须放,别用 SVG 假冒。**别以"克制"为由砍掉本该承载内容的真实照片**——那不是克制,是丢内容(见 T1)。
- **统一 + 适配**:全套使用同一套选择、裁切、色温、对比与承载方式，不等于所有图片必须同色或去色。自然、物种、艺术品、食物、产品状态、热成像与显微/遥感结果中的颜色常是内容，应保留；需要统一时优先做轻量而可逆的调和。只有 Style Lock 给出与主题相关的明确理由时才统一低饱和或 duotone，且不能让整册证据照片失去颜色信息。image brief 指定画面主体 + 宽高比(匹配版式槽位)+ deck 主色 / 色调 / 情绪。父级调用 `generate_image` 时按内容指定 `$DECK_DIR/assets/` 下的稳定输出路径，把工具返回的确切路径原样回填并登记来源；Slide 引用回填的真实路径，不自行编造文件名。
- **★图片先定占位、按槽位比例出图、别被裁(治「模板图经常显示不全 / 主体被裁」)**:顺序是 **先排版定图片槽位 → 记下槽位的宽高比 → 按这个比例出图 / 搜图 → 图完整填入槽位**,不是"先随便出张图再硬塞进不匹配的框"。
  - **规划期**:每个 `image:` 槽在 `plan/slide_NN.md` 写清**目标宽高比**(如 16:9 满幅、4:3 半栏、1:1 方图、3:4 竖图),image brief 里记录该比例；调用 `generate_image` 时将目标比例转换为 `WIDTHxHEIGHT` 格式的 `size` 参数（见 `references/box-agent-tool-contract.md`），或搜图时挑接近比例的候选。
  - **渲染期**:图槽宽高比 ≈ 图本身比例时用 `object-fit:cover`(填满不变形、少量裁边);**比例差得多、或主体不能被裁**(人物 / 产品 / 完整图表 / 分镜)时用 `object-fit:contain`(留边但主体完整),别用 cover 把主体裁掉。**主体必须完整呈现的图,宁可 contain 留边,也别 cover 裁头裁尾。**
  - 判据:上屏的图**主体完整、不缺头少尾、不变形**;做不到就换比例更配的图或改槽位。
- **★配图形状别一刀切直角矩形(治「配图形状太单一、每张都一个方框」——`⚠` 无机核,靠这条自觉)**:图片框不是只有"直角矩形"一种。按页面气质给图**恰当的形状节奏**,`base.css` 已备形状库(`.ph-shape` + `.ph-round/-round-lg/-circle/-pill/-arch/-arch-top/-angled/-hex/-blob` + 描边 `.ph-frame`/`.ph-mat`):
  - **人像 / 单主体** → `.ph-circle`(正圆)或 `.ph-arch`(拱门)最讨喜;**宽幅场景** → `.ph-round-lg` / `.ph-pill`;**编辑 / 文旅 / 杂志风** → `.ph-arch`(门洞)有格调;**科技 / 发布会** → `.ph-angled`(斜切)/ `.ph-hex`;**生活 / 活泼** → `.ph-blob`(有机形)。
  - **纪律**:① 形状**服务气质**、别为花哨乱套(党政 / 学术等庄重题材克制用 `.ph-round` 足矣,别上 blob / hex);② **一页别混超过 1–2 种形状**、全套成系列(同类图用同一种形状,别每张一个样);③ 形状是节奏调剂,**主体可读性优先**——圆 / 拱 / 斜切都可能裁掉边角,主体不能被裁的图别用会切主体的形状(回 `.ph-round`)。
  - 判据:一套 deck 的配图**不是清一色同尺寸直角方块**,有恰当的形状 / 描边变化、但克制成系列,不杂乱。
- **★封面不素，但不设固定层数**:主视觉与标题先构成完整焦点；只有确实增加主题理解、身份识别或构图张力时，才补副标题、用户明确提供且听众需要的真实场合/机构/日期信息，或一个可贯穿全册的语义母题。每项辅助元素都做“删除测试”：删掉后信息与构图都不受损，就不要放。不得为了显得“设计过”编造 `SCENE / COVER / END / CATALOGUE NO.`、坐标、页数、时长、年份、制作状态或重复作品名；也不得把内部的主体、受众、目标、页面角色、素材路线写到屏幕上。素的反面是层级、尺度、裁切、色场、材质和留白之间的关系，不是标签越多越高级。
  - **可用信息层**:凝练副标题；用户提供的真实机构/场合/日期；真正有语义的母题或 accent。它们都必须服务听众，且主题、作品名、年份、场合各出现一次即可。
  - **不可用填充层**:假技术注、假档案号、假场景编号、普通页页脚/页码、重复 title/kicker/meta、内部计划字段。
  - 判据:封面一眼有焦点、标题层级清楚、主视觉与文字形成关系；辅助元素少而准确，没有任何一项只是为了填空。

## 7 · 版式多样度(arch-*)

base-template.css 备了 **8 个视觉明显不同**的 `arch-*` 版式原型,plan 每页「版式」行可点名一个:`.arch-hero-stat`(单焦点巨数字)/ `.arch-index`(编辑大序号清单)/ `.arch-sidebar`(窄栏 + 宽内容)/ `.arch-quote`(排版打断金句)/ `.arch-timeline`(横向时间轴)/ `.arch-diagram`(Canvas / 图片概念图框)/ `.arch-compare`(并列对比)/ `.arch-feature`(非对称单主体)。它们只定结构骨架,配色 / 字体仍全走 token。**arch 是可变形原型,不是必须照抄的模板**:内容需要时可以调整比例、顺序、图槽、图例、Canvas 画布,只要仍在 `.slide-body` 的 grid/flex flow 内、且不破坏全局骨架。

- **多样度按表达需要判断**:相邻页面避免无理由复制同一几何；当内容角色、媒介或阅读动作变化时，构图也应变化。不要为凑 `arch-*` 数量强行换版式，也不要把不同内容都塞进同一安全卡片墙。
- `.arch-index` 大序号清单只用于真顺序（步骤 / 时间线 / 排名），平行 / 非顺序要点不用编号伪造推进。
- 自检看页面地图中的构图方向、媒介、信息密度与阅读动作是否形成节奏，而不是 grep 类名计数。

## 8 · 页内密度(展开见 §T1)

- **★密度按「使用场景」定(不是越少越好、也不是越多越好)**:先判场景——**阅读 / 技术文档型**(技术方案 / 研报 / 数据分析 / 培训 / 年终总结):每页信息密、数据 / 表格 / 图表多是**优点**,别怕密;**演讲辅助型**(大会 / 发布会 / TED):每页少量关键词 / 短句,精简凝练是优点;**汇报型**(工作汇报 / 项目进展 / 商业计划):居中。密度**匹配场景**才算对。⚠️ **密度 ≠ 文字量**:满页框架短语(「提升触达」「品效合一」)却无具体数据 / 案例 = 有效密度仍低。
- **每页内容均匀铺满 `.slide-body`**,别一块挤死、一块大留白。**走结构解,别缩字号也别硬堆内容**:竖向匀 → `.slide-body.even`(等高网格);横向匀 → 网格 / 分栏对齐(`.grid-2`/`.grid-3` + `.even`);一排卡片尺寸统一(`--card-min-h` / `.panel.uniform` / `.col`+`.foot`);图表页套 `.figure`;图文比例锚定(`.arch-feature` 1.62:1)。
- **两种真硬伤**:① **溢出**——任何页内容挤到出血 / 截断 / 贴边压边 = 硬伤回排(密文拆页,别缩字);② **懒散空**——内容页留白过半却不是刻意的 breathing / hero 单焦点页 = 回排配满。**但刻意的 hero / breathing 单焦点页就该大留白**——那是节奏对比、不是「不均」。
- **任一内容页围绕一个主判断组织**；支撑信息数量按场景与论证需要分配，能清楚形成层级即可。别把无关判断混成一页，也别用固定条数把复杂内容削薄；跨页密度应有节奏。
- **有效密度先补语义，不补重复标签或装饰**：普通内容页除了主判断，还应由证据、机制、对比、案例、行动或边界中的合适一层继续解释；没有新的支撑价值就合并或重构，而不是把同义标题、状态角标和大块空白算成“简洁”。标题、subtitle、图片角标、badge、callout 和图例中的同一短语通常只保留一个最强载体；导航或同屏对照确需重复时，每次出现必须承担不同作用。
- **★留白要有归属、别塌底(治「下方留白过多 / 单边死白」)**:撑不满一页 → **放大主体 / 加呼吸 / 合并页**,不是把内容钉在顶上、底部塌一片空白——**禁单个 `margin-top:auto` 钉底**;满屏 flex 纵向列用 `justify-content` 把纵向余量摊匀(或 `.slide-body.even` 等高铺)。并列卡 / 两栏用 `align-items:stretch` **等高**。**每块空白都要说得出理由**;说不出理由的单边 / 单角意外空白 = bug。**整页视觉重心尽量落在画布中心区**(`render.py` 的 `⚠ VBALANCE` 会点出偏移)。密度求「匀」不是求「满」也不是「空」——行距保持舒适(正文 1.5)、元素间距适中(留白花在**分组**上体现层级)。
- **自检**:一排等高网格各列内容量目测齐平(`arch-feature`/`sidebar` 故意不对称的除外);没有「留白过半又非刻意呼吸」的内容页;跨页密度别忽高忽低。配平靠内容 / 网格,别缩字号。

## 9 · 布局规整

AI deck 显「乱」的根因多是**对不齐 / 单元不同构 / 装饰散撒**,skill 系统强制、别指望子 agent 临场发现:

- **① 重复单元固定行槽 + 等高对齐**:一排 KPI 卡 / 版块 / 时间线列,内部元素(图标 / 名称 / 大数字 / pill / 脚注)各占固定高度行槽,各单元同一 y 基线对齐;给 `.num`/`.label` 设 `min-height`、卡片 `.col`+`.foot` 等高、`align-items` 顶对齐。
- **② 同组单元同构**:一组并列卡片用同一套内部布局,平行内容 → 同构版式。
- **③ 统一栅格 + 统一边距**:全 deck 每页同一 safe-margin + 列栅格,元素吸附栅格线。
- **④ 间距走固定档**(8 / 16 / 24 / 32 / 48),同类间隙一致。
- **⑤ 装饰结构化别散撒**:漂浮圆点 / 色块 / 卡通形状应贴边、成组或对齐栅格，数量服从构图且不抢主体。**装饰线(分隔线 / 暗线 / kicker 短线)全套统一**:同角色的线长短、粗细、行间距、缩进一致;**禁无理由的杂散线**——标题右侧凭空一条竖线、某页多一根分隔线这类**规划外多余装饰**一律删。
- **⑥ 一页一套对齐轴 + 整体居中 + 元素间真对齐**:主体统一左对齐或统一居中,别一页混左 / 中 / 右;**元素与元素之间要么共一条轴(共左线 / 共基线 / 共中线)、要么明确水平 / 垂直居中,别「差一点没对齐」的半吊子漂移**(错位感头号来源)。整版视觉重心居中,别偏上 / 偏下 / 偏侧。
- **⑥b 布局尽量均匀 + 无意义留白当缺陷**:内容匀布满安全区——短内容整体居中撑开、内容多就拉层级 / 加分区填匀(见 §8)。⚠️ 区分**有意义 vs 无意义留白**:封面 / 章节页 / hero 的大留白、元素间的呼吸间距是有意设计(留);正文页某侧大片空、内容缩在一角、行 / 块之间无理由大缝是无意义留白(去)。
- **⑦ 渲染诊断与像素裁决**:`render.py` 的输出先用于定位候选，最终判断以新鲜 PNG + DOM 为准。`OVERFLOW`、`TEXT-OVERFLOW-BOX`、`FOOTER-PUSHED`、`BROKEN-IMAGE` 若证明真实裁切/缺失就是硬伤；`OVERLAP`、`DECOR-OVERLAP`、`FOOTER-COVER`、`INNER-GAP`、`WIDOW-LINE`、`IMG-LONELY`、`VBALANCE`、`COVER-OOB` 和旧 SVG 告警需先确认像素中确有遮挡、不可读、空洞或语义损失。bbox 包含透明行框，不能单独证明字形相撞；有意层叠按真实可读性判断。不得为清警告删除有效内容、增加突兀托板、缩小主图或破坏构图。
- **⑧ 页面标题同锚点(跨页钉死)**:所有内容页的 `.slide-title`(眉签 + 主标题)在**同一位置 / 字号 / 字体**渲染(别在个别页改标题字号 / 挪位 / 加长到折行顶高标题区)。英文双语副题 / 章节英文名「要么每页都有、要么都没有」。
- **⑨ 同权重信息同款式**:同一层级 / 重要性的信息(并列小标题、并列数据项、同类标签 / 序号体例)用同一颜色 / 字体 / 字号 / 标号写法;只有表达强调层级差异时才变款式,且变色 / 变号必须与内容含义挂钩(见 §1「改色要有逻辑」)。
- **⚠️ 不牺牲活泼**——配色 / 图标 / 插画照样活泼,只是骨架必须规整。

- **⑩ 内容量适配容器(治「卡内留白过多」和「内容溢出」同源)**:卡片 / 框 / 网格格子的**高度由内容驱动**,别用定高硬撑——
  - **内容少的卡别撑高留空**:一排卡片内容量不等(如 P0 只 1 条、P1/P2 各 2 条)时,别让所有卡强行等高把少内容的卡撑出大片空;优先缩短卡高或重排网格。若同组卡必须等高且每张都只有“图标 + 标题 + 一行说明”，把这整个内容组**垂直居中**，图标和文字仍沿共同左轴排列；不要把三行内容钉在卡片上沿。只有单个数字、单词或极短状态才适合整卡水平居中，段落、清单和中英文混排继续左对齐以保持扫描效率。可放大图标、标题和有效说明建立层级，但不得为了填空编造一行内容。
  - **内容多的别溢出**:放不下就**减字 / 缩字号一档 / 拆两页 / 换更紧凑版式**,绝不让文字溢出卡片或被 `overflow:hidden` 裁掉；告警先与新鲜像素/DOM 对照，确认真实溢出后修根因。
  - 判据:一页里同排卡片的**内容饱满度目测相当**,没有"一张挤满、一张半空"。
- **⑪ 禁不必要换行 / 寡行(治「一行写得下偏换行」「幕/满格 单字成行」)**:
  - **换行必须落在语义边界**:标题、副题、正文、批注、金句和标签无论是手动 `<br>` 还是容器宽度造成的自动换行，都必须优先落在标点、并列分隔或完整短语 / 语义单元之后。禁止拆开动宾短语、偏正短语、固定搭配和仍需依赖上一行才能成立的语义片段；若自动换行落点不自然，必须通过调整容器宽度、字号、字距或改写文案修正，不能以“浏览器自然换行”为由保留。
  - **禁止 1–2 字寡行**:普通文本任何一行，尤其末行，不得只剩 1–2 个汉字；不得把「满格」「幕」「风险」等短尾甩到下一行。应优先拓宽文字块、移除多余 `max-width`、微调字号 / 字距或在不损失信息的前提下改写，不得靠压缩整页或牺牲可读性规避。
  - **别手动 `<br>` 断错位置**:一行能排下的短语(标题副题、批注、金句、标签)**不要手动断行**;让它自然排,或用 `text-wrap:balance`(标题)/`pretty`(正文)自动均衡。只有确实需要控制阅读节奏时才使用手动 `<br>`，且仍须同时满足“语义完整”和“无 1–2 字寡行”。
  - **容器别掐太窄逼出寡行**:托板 / 卡片 / 文字块的 `max-width` 要能容下自然行;明明版面有横向空间却因容器窄把一句话挤成多行 + 末行孤字 = 改宽容器 / 去掉多余 max-width。
  - **专名不拆**:数字+单位、地名 / 人名 / 机构名用 `white-space:nowrap` 不拆行。
- **⑫ 大标题挤 → 收字号,别硬撑(治「粗衬线 / 超粗黑大标题字挨字、压迫」)**:粗宋(900)/ 得意黑等**粗重字**做大标题时,内容一长就显挤——**标题变长就降一档字号**(别死守 `--fs-title`/`--fs-display` 最大值把长标题硬塞成满屏粗字),保证标题**一行舒适排下**、字与字有呼吸;粗中文大字**别再叠负字距**(`letter-spacing` ≥0,负字距是给拉丁展示字的,加在粗中文上更挤)。标题长度控制在 1 行(最多 2 行短语),排到顶宽就是该缩字号的信号。
- **⑬ 卡内分隔线 / 装饰线条件化(治「内容少时线突兀 / 重复线」)**:卡片内「正文 ↔ 脚注(负责人/产出/来源)」之间的分隔线,**只在正文与脚注之间真有内容分区时才画**;若卡片内容少(正文就一行)、线上方大片空,则**去掉这条线**或让内容撑起来再画。一排卡片要么**都有线且线的 y 位置一致**(靠 `.foot` 顶底对齐)、要么都没有,别有的卡线悬在空中。
- **⑭ 封面 / 文字块重心别偏上(治「封面标题太靠上、下方大片空」)**:封面 / hero / 过渡页的文字块要**在安全区内视觉居中或有意的构图位**,别一律顶对齐把标题贴到顶边、下方留一大片无理由空白;顶部留足安全边(≥ `--margin-y`)。左侧竖排文字块(序号+标题+副题)整体在竖向**居中**,不是钉在上半部分。（`⚠ VBALANCE` 会点常规内容页的重心偏移；封面重心靠这条自觉。）
- **⑮ 局部间距别挤(治「脚注贴正文太近、图贴框底」)**:脚注 / caption 与上方正文之间留**足够呼吸间距**(≥ `--space-3`,别贴到一起分不清层级);卡片 / 框内的图片、正文与框底之间留 padding,别让内容贴框边 / 贴框底。事实来源不占画布,统一进入 `speech.md`。
- **⑯ 序号 / 大字 与 右侧标题「顶端对齐」(治「标号和文字顶端没对齐」)**:大号序号(`.no`/`.idx` 48–64px)+ 右侧小号标题(26–32px)并排时——
  - **横排容器用 `align-items:flex-start`**(顶对齐),**绝不用 `align-items:baseline`**(大字小字按文字基线对齐 → 大序号顶端必然低于小标题顶端,就是「没顶齐」的根因;和 §T2 单位对齐是同一类"大字+小字裸 baseline"陷阱)。
  - **序号 `line-height` 别压到 1**:序号 `line-height:1` 会让数字在行盒里贴底、顶端下沉;设 `line-height:1.05~1.1`(贴近标题首行行高),两者顶端才真齐。
  - **右侧标题别加 `padding-top` 把自己往下推**(那会让"顶齐"又错开)。
   - ⚠️ **页面内联重写 arch-index / 序号清单时,也必须守这条**——别照抄旧的 `align-items:baseline` + `.no{line-height:1}`(base.css 原型已是 `align-items:start`,内联别覆盖回 baseline)。
- **⑰ 别让「等分网格 / 定高区 / 巨字号」制造溢出与空洞(治「文字撑出文本框」「卡片中间莫名空一块」「多区堆叠底端溢出」「封面标题快出界」——`⚠ TEXT-OVERFLOW-BOX` / `⚠ INNER-GAP` 的根因)**:
  - **外层正文区只能有一个高度所有者**:`.slide-body` 若由 absolute 的 `top + bottom` 定高，就保持 `height:auto`;若由 flex 的 `flex:1` 占满剩余空间，也不要再给它 `height:100%` / 固定 px。`top + bottom + height` 或 `flex:1 + height:100%` 会让正文区越过页脚，即使内部看起来还有空间。页面专属满高网格放进 inner stage，并给 inner 的 grid/flex 子项 `min-height:0`；不要覆盖外层正文区的位置、高度和 overflow。
  - **等分网格承载不等量文本 → 会撑破也会留空**:`repeat(N,1fr)` / `grid-template-rows:repeat(N,1fr)` 把每格钉成等高,内容多的格文字**溢到框外**(盒是 `overflow:visible`、不被裁、也不超整页 → vision 与 OVERFLOW 都漏,`⚠ TEXT-OVERFLOW-BOX` 专抓)。**别靠 1fr 硬撑不等量文本**:改 `grid-auto-rows:auto` / `align-content:start` 让格按内容高、内容多的整体降一档字号或减字,保证最满的一格也在框内。
  - **禁 `margin-top:auto` 制造卡内空洞**:flex-column 卡里用 `margin-top:auto` 把末块(描述/脚注)顶到卡底,当卡被等高网格拉高、内容又少时,chip/正文 与 末块之间裂出一条大死白 = "中间莫名空一块"(`⚠ INNER-GAP` 抓)。**卡内容按需高 + `align-content/justify-content:start` 顶排**;要贴底脚注就让**整排卡的脚注 y 位置一致**(靠内容自然撑,别靠 auto 撑空)。
  - **多区纵向堆叠页禁用固定高度补救**:一页里上区+表+多条流程等多块纵向堆叠时,给外层或某块写死 `height:302px` 之类,后面 `flex:1` 的块累加超过 900 就从**底端溢出**；把外层从错误的 `height:100%` 改成另一组固定 px 也只是偶然适配当前画布。改 `minmax(0,1fr)` / `flex` 让各区按可用高自适应;真放不下就减节点/拆页,别定高硬塞。
  - **封面 / hero 巨字号别用固定 px + `nowrap` 顶安全区**:`.cover-h1` 之类固定 `font-size:132px` + `white-space:nowrap`,标题一长就冲出左右安全区(几何可能没超整页、但观感"快出去了")。用 `clamp()` 或**按标题字数降档**,并守住 `--margin-x` 安全边;长标题宁可换行(`text-wrap:balance`)也别硬顶出界。(`⚠ COVER-OOB` 会点封面标题贴到 / 越出安全区。)
- **⑱ 对齐 + 间距 = 大众审美的地板(治「视觉重心不均、东西没对齐、间距忽大忽小」——`⚠ VBALANCE` 管重心,对齐 / 间距靠这条自觉)**:普通人一眼觉得"专业 vs 业余",八成看的是对齐和间距是否规整,不是花哨。守四条:
  - **共对齐轴**:同页元素**共用少数几条对齐线**(左边界线 / 网格列线 / 基线)——标题、正文块、卡片、图、页脚左缘尽量**共左线**;并排块**顶对齐或基线对齐**(见 ⑯);别每块各自缩进一点、参差不齐。数字列 / 表格数字**右对齐或小数点对齐**(`tabular-nums`)。
  - **间距成体系**:块间距**用 `--space-*` 阶梯**(别一处 13px、一处 27px 手写乱值);**同级元素等间距**(一排卡 gap 一致、一列条目行距一致);**层级靠间距差表达**(组内紧、组间松),而不是随手留白。
  - **视觉重心居中 / 撑满**:常规内容页主体在安全区内**垂直居中或撑满**,别整体偏上 / 偏下留一条无理由空带(`⚠ VBALANCE` 会点);左右也别一侧挤满一侧空(除非有意的非对称构图 + 明确重心)。
  - **对称 / 网格优先,非对称要有理**:拿不准就用**规整网格 / 居中对称**(大众审美安全区);要用非对称构图必须有清晰的主次和视觉引导,别做成"看着就是没放齐"。判据:眯眼看整页,元素落在清晰的行列格线上、间距均匀、重心稳,没有"这块怎么歪着 / 这里怎么空一条"的别扭感。

## 10 · 最小字号(可读地板)

- **正文 / 标签 / caption / 图内注记 / 轴标签 / 图例别刻意缩到 `--fs-min`(出厂 20px、常规下限 ~18–20px)以下**;含 Canvas/HTML 概念图标签、ECharts 的 `axisLabel`/`legend`/数据标注同样 ≥ `--fs-min`。图里塞不下就**精简标签**(只标关键项),别靠缩字硬塞。
- **优先级**:适合内容的版式与真正解释关系的概念图 **>** 为填满画面盲目放大字号。不要为了满足类数凑 arch，也不要为了凑字号砍掉有价值的图解。
- **小字用色**:说明 / 来源 / 脚注 / 标注 / 时间轴标签一律用 `--ink`(别用 `--ink-dim`)且对底 ≥4.5:1(见 §对比度 T2);`--ink-dim` 只用于 ≥18px 的次要文字。
- ⚠️ 别用「把 `--fs-min` 声明得极小」假合规——渲染后小字仍得人眼真能读,复审会抓。

## 11 · 反 AI 味(anti-slop)+ soul

- **精确 anti-slop 清单(设计自检,踩到即改)**:⛔ 7 个靛蓝 / 紫默认 accent hex `#6366f1` `#4f46e5` `#4338ca` `#3730a3` `#8b5cf6` `#7c3aed` `#a855f7`(主题真要靛蓝就经 `--accent` 有意声明);⛔ emoji 当功能 / 项目图标(✨🚀🎯⚡🔥💡📈…)→ 1.6–1.8px 描边 monoline SVG(`currentColor`)或不用;⛔ 编造指标(「10× faster」「99.9% uptime」)→ 有真实来源或标占位(「—」/「待核」);⛔ filler 占位文(lorem ipsum / feature one·two·three)→ 空版面用构图解决;⛔ 圆角卡 + 左侧彩条 accent(AI dashboard tile)→ 去圆角或去彩条;⛔ 外部占位图 CDN;⛔ **裁字渐变**(`background-clip:text` 渐变标题)⛔ **卡套卡**⛔ **标题上方圆角方形图标块**(icon-tile)⛔ **双轴发丝网格背景 / 无主题、反射式复用的标题后圆形径向光斑**(codex grid / dark-glow)⛔ **反射式 Fraunces / Instrument Serif**(主题真要编辑感才点)⛔ **破折号 `—` 当装饰**。不用 Inter / Roboto / 系统默认显示字体,不要什么都居中,不要无意义毛玻璃。⛔ **占位符残留**(`--`/`-.--%`/空数据槽出屏)——填真值或删该槽,不要把制作状态呈现给听众。
- **卡片宫格避免机械重复**:等权卡片只在内容确实平行且需要快速扫描时使用；相邻页或整章反复出现“眉签→大标题→一排等权卡片”时换成更适合内容的图文、流程、对比或主视觉构图，不按固定页数配额判断。
- **构图 / 审美负面清单(非机核,靠自觉,治「一眼廉价 / 模板 / 土 / 素」)**:⛔ **通用居中标题栈**(什么都水平居中堆一摞)→ 用对齐轴 / 非对称重心(见 §8.5);⛔ **多色平均分布**(每块一个色、彩虹平铺)→ 主色统治 + accent 点睛，每种色有语义;⛔ **满版传统纹样 / 花边框**(整页四周包一圈装饰纹)→ 纹样只做局部母题或低对比托底;⛔ **旅游纪念品感**(把文化符号 / logo / 传统器物直接放大贴上去当唯一创意)→ 经比例 / 裁切 / 重构翻译成当代图形;⛔ **整页平均用力**(信息 / 细节均匀铺满、无主次)→ 细节集中局部、其余留白安静;⛔ **模板感**(一图一字、无设计概念、换个主题也认不出)→ 见 §8.5 编辑动作 + soul 自评。这些是「素 / 土 / 廉价」的常见根,配合 §T1「高级 8 条」与上面 anti-slop 机核清单一起用。
- **soul 自评(80 / 20)**:~80% 成熟稳妥版式 + ~20% 一处大胆(一个排版决定 / 一处配色 / 一个反常比例 / 一句有声音的文案)。检验:把成品截图给圈外人看,认得出是哪个主题 / 产品 → 有 soul,认不出 → 只是模板。

## 12 · 逐页节奏 + 设计概念

- **为页面声明节奏角色**:`anchor`(章节起始/关键页)、`dense`(信息密集)、`breathing`(低密度+单焦点)。角色按叙事推进安排；相邻页面若连续同构且没有作用，就调整构图或密度。breathing 页不应用卡片墙把留白重新塞满，也不要求每一幕机械凑齐所有角色。
- **写一句「设计概念」进 `plan/deck.md`,让形式服从它**：讲「简约」的主题自己就要简约，别用塞满的宫格去讲简约。封面母题在足以建立整册亲缘性的关键页面以变体回应；不要只用一次就丢，也不要为满足次数机械贴装饰。一个背景装饰若删掉也不丢东西，它就不是美术指导，删。
