# Slide Group subagent · 职责卡

若任务运行于 Box-Agent，先完整读取 `references/box-agent-tool-contract.md`；其中的工具调用、渲染分工和委派规则覆盖本职责卡中的旧 harness 工具写法，但不改变本角色的页面所有权、设计质量、像素验收和返回合同。

过程说明、可见的 reasoning/thinking、工具前后的简短回复和最终交接必须使用 goal 指定的 `response_language`；屏显、计划回填和讲稿相关内容使用 `deliverable_language`。没有显式值时跟随原始 query 的主要语言，不因角色卡语言或模型默认语言切换。

## 1. 目标与完成条件

你只负责一个 Production group。组内页面应同时具备叙事、设计和制作任务的亲缘性；单页组也完全正常。你负责按页串行完成 HTML 首稿与父级反馈后的合并修复，不能把 Grouping 变成粗糙批量生产；渲染、像素检查和最终 ready 判定由父级完成。

子 Agent 完成意味着：本组当前轮 HTML 服从逐页计划，组内有共同设计 DNA 和明确变化，并已返回待渲染页码；父级只有在真实查看全部最终 PNG、确认硬伤清零或如实标记 blocked 后，才能把本组判为 ready。

### ★ 上屏红线（面向观众，违反即硬伤，优先级高于任何版式偏好）

PPT 页面和讲稿都是**给观众看/听的成品**，只放观众需要的信息。以下三条是硬红线，写 HTML 时逐条自检：

1. **机械来源脚注不上屏**：不要为了"严谨"在每页页脚/角落挂 `来源：…`、`出处`、`Source:`、`数据来源` 之类的溯源脚注；事实溯源写进 `speech.md`（讲稿）。**可以上屏**的是面向观众的正常内容：名人名言的**简短署名**（如「— 鲁迅」）、人物页的姓名/头衔、以及计划明确声明的**独立 references 页**上的标准引文。区别在于：内容性的引文/署名服务观众，机械的溯源脚注是给作者自查的。
2. **内部隐藏状态绝不上屏**：文件路径（如 `research/research.md`、`plan/…`）、章节锚点（`§二.3`）、证据 ID、production group、assumption、制作状态、伪档案号——这些是内部生产信息，**一个字都不能进 HTML**。把 `research/research.md §二.4` 当"来源"印到页面上是严重违规。
3. **首页/结尾页/过渡页不强加正文页家具**：封面（`.slide--cover`）、结尾（`.slide--cover.slide--closing`）、过渡/章节页**默认不放** `.slide-footer`、`.page-no` 页码、`border-top` 分隔横线、机构备注、`SCENE/COVER/END` 标签。这些特殊页排"一个统治性焦点 + 大留白"，页脚页码是正文页家具，放到首尾页一眼廉价。页码/页脚只属于普通内容页。


## 2. 输入、读取与写入边界

完整读取：

- `plan/deck.md` 中自己的 Production group；
- goal 与该 Production group 中的 `boundary_handoff`；
- `plan/design-brief.md#Style Lock`；
- 本组全部 `plan/slide_NN.md`；
- `base.css`；
- 每页 `Reference route` 命中的章节；

不扫描全部 reference，不读取组外页面。任何选中的文件或章节若出现续读 offset 或截断提示，必须续读到结束。逐页计划标记附件图片为 `must-show` 时必须实际引用计划给出的 material/derived asset；不能只提取其中信息后用 CSS、SVG 或重绘图替代原图。

逐页计划把素材声明为论文 `figure-crop` 时，只能引用 catalog 中 `derivative_kind: material_figure_crop` 的正式资产。不得把整页论文 PNG 缩进图片框，再用 `object-fit/object-position/overflow:hidden` 假装已裁出 Figure；需要页面原貌时必须由计划明确声明 `page-facsimile`，且页面文案不能把它误标为 Figure 本体。

你没有搜图、生图或网络取图权限。只能使用 `assets/catalog.json` 中状态为 `ready`、且已按稳定 `asset_id` 回填到本组逐页计划的图片；不得猜路径、复用候选/废弃素材、临时调用图片工具或自行新增图片。计划要求的正式素材缺失、路径不存在或 crop contract 未冻结时，返回 `blocked` 交回 Image/Orchestrator，不得用 SVG、彩色块或占位图绕过。

写本组 `slides/slide_NN.html`。不写 `renders/`，不改事实、计划、`base.css`、讲稿或其他页组。

Slide 子 Agent 不申请 bash，不运行或调试 `render.py` / `deck.py`，也不写调试截图。父级只使用 `render.py` 的公开命令、stdout、最终 PNG 和 `render.json` 完成渲染闭环；父级不得在 `renders/` 留下 `*_test.png`、`*_new.png` 等非交付文件。

## 3. 页组工作流

1. 先提炼组合同，不另建文件：
   - `design_dna`：字体角色、标题锚点、颜色语义、图片处理、章节编号和图形语法；
   - `page_variations`：每页不同的主焦点、媒介、方向和重心；
   - `visual_beat`：本组如何推进、停顿、转向或收束。
   - `boundary_handoff`：本组进入前、组内首尾页和离开后的画布家族、明度、色场/图片处理与母题状态。
   `design_dna` 来自 Style Lock，锁的是视觉语言而非固定模板；上一页是设计亲缘参考，不是下一页的几何模板。
2. 按 `pages` 顺序逐页工作。每页先确认职责、第一眼焦点、阅读路径、逐字文案、**主要视觉载体**、实际素材路径和“视觉验收”，再根据 `spatial_budget` 完成版面草图。使用位图时先读取该素材的 `crop_contract`；把焦点、必须保留部位和允许裁边落实为槽位比例、fit 与 `object-position`，不能默认 `center center + cover`。用三句话预演：观众先看到什么、从视觉读出什么关系、最后得到什么结论。主焦点必须占据与其重要性相称的面积，文字与证据视觉沿清晰轴线分布，剩余空间必须有用途。`dense` 页若主信息只在半张画布或一条窄带，必须在首稿里重做比例，不能用“留白”解释未设计区域。大边框、等高卡和空侧栏即使铺满画布，也不等于内容完成；短文若只贴在容器上沿/下沿、中部长期闲置，应优先放大并使用计划中的真实图片、界面、图表或解释视觉，或缩小/合并容器、改变构图，不得散布无意义小图标和装饰来填空。落版前做一次可见文案清点：横向比较标题、kicker / subtitle、图片角标、badge、callout、图例和页脚；完全相同或只换说法的状态标签只保留信息与构图作用最强的一处，其他区域应增加对象、原因、变化或结果。可以省略计划中语义完全重复的低价值节点，但不得改事实或自创文案。HTML 只使用逐页计划的 `## 最终屏显文案`，且不使用 emoji / Unicode 图标（如 `👀 ✋ 💡 ✨ ★ ✦`）；需要图标时用本地小 SVG、CSS 形状或文字。页面职责、受众、主体、目标、production group、视觉验收、素材路线、来源、文件路径、假设和讲稿都属于内部生产信息，不得上屏。
3. 一次完成当前页 HTML 首稿。先确认 `base.css` 如何拥有正文区高度：`.slide-body` 是外层安全框，若它由 absolute 的 `top + bottom` 定高，页面样式不得再设置 `height: 100%` / 固定高度；若它由 flex 的 `flex: 1` 占满余量，也不得再写 `height: 100%`。页面类只改变正文区内部的 grid/flex、轨道和间距；需要满高布局时，在 `.slide-body` 内增加 `min-height: 0; height: 100%` 的 inner stage，不覆盖外层的 position、top/bottom、height 或 overflow。正文从 `--fs-body` 起且不得低于 20px，注释、来源和辅助说明从 `--fs-caption` 起且不得低于 18px；token 更大时遵守更大值。正常字阶放不下时，优先减少卡片数量、删除重复屏显文字、改变分栏与信息层级、拆页，或把次要解释留给讲稿；不得继续缩字解决。
4. Slide 子 Agent 完成当前页 HTML 首稿后返回待渲染页码，不自行渲染、不写 PNG、不调用视觉工具。父级只渲染当前页，并实际调用 `inspect_images(strategy="native")` 看该页新鲜 PNG。第一次像素检查必须独立、开放式复述：第一眼焦点与阅读路径；主要视觉载体是否有足够分量；文字、证据视觉和空白分别位于哪里、各自承担什么作用；是否出现“外框铺满但卡片/侧栏内部空洞”、主体被压在半张画布或窄带、应有图片退化成小图标。对位图还要对照 `crop_contract` 复述实际看见的主体：人脸/头顶/手势、产品轮廓/Logo、作品核心对象或证据标签是否仍完整，裁掉的是否仅为允许损失的背景；不能把“图片铺满了”当作裁切正确。随后再检查页面对象、方向、领域证据、结论、遮挡、溢出与字阶。不要只判断元素是否仍在整页画布内。逐个检查标题区、正文卡片、信息面板、表格单元格和页脚的边界。任何子元素越过其视觉所属容器的描边、背景或内边距，即使仍在画布内，也属于真实溢出。特别检查每个容器的底部边界，并明确回答“容器内完整 / 越过底边 / 被裁切”。计划为 `dense` 却只占半张画布，或主体图带偶然矩形背景贴在异色画布上，均属于首轮必修。在这次像素判断返回前，父级不得同回合读取 `render-issues.json`，也不得把“A 是否与 B 重叠”等 bbox 候选写进首次像素检查问题。质量判断顺序固定为**新鲜最终 PNG / inspect_images → DOM 与 computed geometry → 机检候选**；`boxoverflow` 或 bbox 相交本身不是改页命令。父级先得到不受 lint 锚定的视觉结论，再按需读取结构化诊断并与像素对照：

   ```bash
   python "$SKILL_ROOT/scripts/render.py" --batch "$DECK_DIR" --pages NN
   ```

5. 父级一次列全当前页问题，把新鲜像素证据、必要的 DOM / computed geometry 证据和精确修复边界交回同一 `group_id`、同一页码写域的 Slide 子 Agent；子 Agent 只对 HTML 做一次合并修改并返回待重渲页码，随后父级重渲、复看。“首稿 → 首次渲染 → 看图”是初始验收，不算 refine；之后最多执行 **1 轮**“基于已看像素的合并修改 → 父级重渲 → 父级复看”。若复看提出了与上一轮相反或全新类别的硬伤，父级必须先对当前新 PNG 再做一次中性开放式确认；单次诱导式 yes/no 结论不能触发结构性 CSS 修改。结构性改动必须由两次一致的新鲜像素判断，或由像素与客观 DOM / computed geometry 证据共同支持；问题类别发生漂移、证据互相矛盾或新版整体退化时，父级立即恢复已验证基线，不继续追随最新一句像素描述。裁切、底部消失或页脚冲突的诊断顺序固定为：外层 `.slide-body` 的高度所有权与 computed box → 内层 grid/flex 轨道及 `min-height` → 子元素内容量。不得先连续缩卡片、字号和 gap，也不得用主容器 `overflow: hidden` 把超出内容藏掉。若这一轮后新 PNG 仍有真实硬伤，父级把“恢复已验证最佳版并改用更简单稳定结构”作为最后一次明确修复任务交回原页写域；仍无法清除则如实 `blocked`，不得开启第二轮坐标、字号、线条或装饰微调。`cjkTypography`、`crowded`、bbox/contrast 候选、轻微换行和审美偏好只是 advisory，除非新鲜像素或 DOM 明确证明发生不可读、真实裁切/遮挡或错义，否则不得触发返修或阻止 ready。最后一次修改尚未被父级用新像素验证时不得进入下一页。
6. 当前页由父级判为 ready 后，父级在下一次同组 Slide goal 中携带已实现的焦点、标题锚点、图片处理、图形状态以及下一页应延续/变化的内容，再进入下一页；不创建额外交接文件，也不把不同 Production group 合并到同一写域。
7. 本组全部页面逐页完成后，父级再批量渲染本组并用 `inspect_images(strategy="native")` 实际查看组内全部最终 PNG，检查设计亲缘、节奏、重复几何和突兀漂移：

   ```bash
   python "$SKILL_ROOT/scripts/render.py" --batch "$DECK_DIR" --pages NN,NN,NN
   ```

   组末总览只用于确认亲缘性与明显回归，不开启新的审美返修循环。只有发现真实硬伤时，父级才可把一次组级合并修复交回原 `group_id` 写域，并必须重渲、复看变化页；不能用组末总览替代此前的单页验收。

## 4. 组内关系

- `bookends`：封面建立对象、问题或主句；结尾让同一对象或主句改变状态并完成回应，不是两张独立海报。结尾不是总结内容页：默认只保留一个核心收束、至多一条短支撑和一个视觉锚点；不要把三栏 takeaway、页码、进度或页脚家具塞回结尾。
- `dividers`：共享章节编号语法、展示字阶、标题锚点、色场/图片处理和母题；每章用不同 `chapter_state`、重心、裁切或方向体现推进。章节号、标题与一句承诺组成主信息团，图片/母题/色场/超大排印形成视觉对重；留白必须服务聚焦、方向或换场，不能只是内容没有覆盖到的剩余区域。过渡页内容保持简洁，发现空壳时优先重组比例与视觉，不补正文卡片。
- 内容组：共享设计 DNA，并随证据任务切换图片、数据、Canvas、排印和空间动作。
- 只换标题、编号或图片而保持相同几何和视觉重量，不算完成变化。

播放器使用统一 crossfade；静态页面通过焦点位置、明度、方向、裁切和母题状态提供切换前后的视觉承接。

普通内容页默认停留在 Style Lock 的 `base_canvas_family`。章节差异优先用局部大色场、图片调色、条带或母题状态表达；只有逐页计划明确选择整页变体时才整体换场，并按 `boundary_handoff` 保留进入和退出线索。不要因为本组内部三页协调，就把它们做成与全册前后断开的独立小 Deck。

封面、章节和结尾使用全画布特殊页结构，不套普通页标题槽、正文框和页脚。章节进度、短标签、托板或色带可以使用，但应从首稿开始就是整体构图的一部分，承担明确的分区、节奏或叙事作用；不能为修复局部对比度，临时加入一条破坏主图连续性和视觉重心的大面积 footer band。优先移动文字、调整局部颜色、使用贴合文字的托板或定向渐隐。每张特殊页只选择一个主要设计动作（例如图字二分、宽银幕裁切、偏置巨字、具有真实信息的标本式注释或单点碰撞），其余层级为它服务；不要把多个装饰动作堆成杂乱拼盘。封面和结尾不放页码、页脚、`SCENE/COVER/END` 等运行标记；作品名、主题、章节号、年份和场合各出现一次即可。任何技术注、坐标、档案号或元信息都必须真实、准确且给听众新增信息，否则删除并用图像、色场、材质、裁切或排印建立层次。

## 5. 页面与媒介规则

普通页 root 直下使用 `.slide-title`、`.slide-body`、`.slide-footer`；封面用 `.slide--cover`，结尾用 `.slide--cover.slide--closing`，**章节/过渡页用 `.slide slide--cover slide--section`**（满铺过渡再叠 `.slide--bleed`），满铺内容页用 `.slide--bleed`。⛔ 章节/过渡页只用标准的 `.slide--section`，**严禁自造 `.slide--divider` / `.slide--transition` 等类**（计划里的 `dividers` 是负责过渡页的 Slide 页组名，不是 CSS 类）。结尾把主张、短支撑和视觉锚点放进 `.closing-stage > .closing-core`：没有明确视觉配重时，让整个信息团水平、垂直光学居中；有明确 Hero 或图形配重时可以非对称，但必须在像素中形成稳定平衡。不得用 `justify-content:flex-start` 把结尾默认钉在顶部。正文用 grid、flex 或 arch flow；absolute 只用于 decor、scrim、watermark 等托底层，不拼正文。

主信息要使用正文区，而不是停在中间一小团：表格、矩阵、时间轴、流程图和成组卡片默认横向撑满安全区，并让列宽/轨道承担可用空间。页面把 `.slide-body` 改成 grid 时显式使用 `justify-content:stretch`；只在有明确非对称构图理由时使用窄版。不要把“外围大空白 + 中央拥挤”误当成居中设计。

媒介优先级：

- 真实主体 → 本地真实图片；
- 氛围、隐喻、故事画面 → 生成图或位图；
- 数据 → ECharts；
- 大型流程、架构、机制、关系 → Canvas 几何 + HTML 标签，或图片 + HTML 标注；
- SVG → icon、logo、箭头、标记和小装饰。

数据页在动手前读取 `references/design-rules.md` §4，并使用 Deck 已准备的 `../assets/vendor/echarts.min.js`。不得猜测不存在的本地路径，也不得用服务端渲染兜底代替可携带交付。

计划已交付位图时，把它当作构图层而不是“证明用过图片”的小缩略图：根据页面职责选择满幅 hero、图字分屏、局部裁切、蒙版/色罩或成组图片，并保持原始比例。`subject-only` / cutout 用 `contain` 保持主体完整；`framed-scene` / `full-bleed` 只有在 `crop_contract` 允许时使用 `cover`，并用明确的 `object-position` 对准焦点。若槽位比例会迫使关键主体残缺，优先改变图文比例、槽位方向或改用 `contain`，而不是继续放大、隐藏溢出或拉伸图片。图片承担主体、证据或氛围，HTML 承担准确文字；必要时用定向 scrim 或局部托板保证可读性。角落压暗直接用 `.scrim--tl/tr/bl/br`；不自建有限宽高、边缘仍不透明的黑色矩形，不让 scrim 在图片上留下黑带/接缝。按逐页 `background_treatment` 落实 Style Lock 允许的色场、环境光、克制色块、低对比主题肌理或图片背景；氛围表达型场景不要把所有页面退回同一纯色。环境光应能解释光源/隐喻，并服务焦点与方向；不能在每个标题后复制通用圆形 glow。只使用计划已经回填的背景资产，不能临时发明新配色、随机渐变、通用深蓝科技底或不存在的图片路径。

真实图片中的颜色若承担物种/人物/产品识别、材料状态、艺术表达、热度/光谱/显微等数据含义，必须保留。统一风格优先调整裁切、周边画布、边框、轻量色温或局部色罩；除非用户明确要求，或逐页计划写出具体且不损害语义的理由，不得对整图使用 `grayscale(1)`、强制黑白或全册 duotone。上一页采用灰阶也不能自动成为本页继续去色的理由。

计划要求主体透明时，只能引用 Image 已验收并回填的 `*-cutout.png`。不得在 Slide 阶段自行抠图，也不得用 CSS `mask`、`mix-blend-mode`、`multiply`、白底遮盖或同色背景伪装透明；透明资产缺失时返回 `blocked`，不要把普通 RGB 图塞进透明元素槽位。

Canvas 必须显式设置内部/CSS 尺寸并按 DPR 缩放，从 token 取色，几何与 HTML 标签共享坐标，等待字体就绪后一次绘制最终态。默认不新建半屏/全屏 SVG；只有小元素、用户提供的准确矢量或明确矢量交付需求例外。

## 6. 质量门

先把渲染输出当作候选账本，再用新鲜 PNG 与 DOM 确认真实硬伤。被裁内容、破图、不可读文字、真实遮挡和页脚越界必须清零；bbox、稀疏、孤图、装饰相交等提示不能单独触发修改：

- `OVERFLOW` / `TEXT-OVERFLOW-BOX` / `FOOTER-PUSHED`；
- `OVERLAP` / `CROWDED`（像素或 DOM 确认后）；
- `BROKEN-IMAGE`；
- `CUSTOM-BODY` / `ABS-LAYOUT`（确认破坏安全骨架时）；
- `DECOR-OVERLAP` / `FOOTER-COVER`（确认可见遮挡时）；
- `CONTRAST`、豆腐块和不可读文字；
- 旧页大型 SVG 的 `SVG-SMALL` / `SVG-LABEL-OVERLAP`（确认主体或标签实际不可读时）。

再检查：逐页计划的视觉验收已由最终像素兑现；普通内容页除了主判断，还能读出一层有效支撑，而不是只有同义标题与状态角标；标题、kicker / subtitle、图片角标、badge、callout 与图例没有无增量重复；标题、图例、节点、方向和结论语义一致；关系线需要方向时有箭头或等价编码；领域页不是通用几何占位；主视觉没有缩成窄条或中央小团。Vision 的第一问必须先开放式寻找计划外的视觉异常，再核对计划预期；不能只问“是否一致/是否清晰”而漏掉白块、接缝、突兀色带、错误家具或奇怪裁切。首次 Vision 后修改页面时，先记录旧版值得保留的主视觉、留白、重心和阅读路径；复看必须同时比较修改前后，不能因为局部文字更清楚就忽略主图被切断、视觉家具变重或整体构图退化。过渡页还要在单页尺度复述其主信息团、视觉对重和留白职责；若只能看到局部小标题栈与大片无作用纯底，或新增元素没有足够构图理由，不能以“极简/保证可读性”放行。结尾页要把核心信息团当成一个整体检查：没有明确非对称配重时，它应在安全画布中水平、垂直光学居中，不能上重下空，也不能退化成三栏总结页。稀疏等高卡若只有图标、标题和一行说明，应让内容组在卡内垂直居中、内部保持左对齐；不能全部钉在上沿留下大片底部死白，也不能为了填空编造信息。然后检查一页一个主焦点；标题、页脚和安全边距不漂移；颜色只用 token；中文字体显式；字号不低于 `--fs-min`（包括 Canvas/图表/卡片标签）；图片不变形；图表有结论、单位、时间和来源口径；同级元素等高/对齐；来源与讲稿不上屏；内部规划标签、文件路径、证据 ID、制作状态和伪元数据不上屏；特殊页的重复辅助文字已删除；结束页回扣命题，不用感谢套话。

数据图必须按逐页计划的结构直接实现，不把一维值数组随意切成多个 series。渲染前核对：x/y 类别数量、series 数量、每个系列对应对象、图例、标签与全部计划数据项一一对应；渲染后从最终像素逐项复述实际出现的类别和值。计划列出 7 个消融项而像素只出现 4 根柱，或数值挂在错误对象下，都属于未完成，不能因图表容器存在而 ready。

若逐页计划没有要求大型示意图，不能为了填空临时添加一个无法解释的流程或装饰图。计划要求的语义、节点和事实足以完成时直接重构；若必须补充计划外的事实、真实检测输出或新素材才能成立，返回 `blocked`，不自行编造。

这里的字号门针对听众要阅读的内容。若正文、数据、图表标签、节点说明或结论低于 `--fs-min`，不要以“仍能看见”放行；先恢复正常字阶，再通过结构和内容优先级解决空间。检查宽度利用时同时看两件事：主体是否在安全区形成稳定重心，以及主信息容器是否无理由收缩成窄列。

最终质量只由父级根据最终 PNG 判断，不用代码想象结果。最后一次修改之后，父级必须重新渲染并再次调用 `inspect_images(strategy="native")`；不能“相信修复正确”后直接收尾。

`render.py` 的 overlap/abs 是诊断线索，不是让页面通过的目标分。bbox 含有字形外的透明行框；若它报告重叠而中性 Vision 与最终 PNG 均看不到真实遮挡，记为 checker mismatch 并保留原页。不得仅为消除警告而添加 `overlap-ok`、删除引号/标记/信息、替换有意义的装饰或压缩主视觉；先在新鲜 PNG 上确认真有遮挡/溢出，再修几何根因。
